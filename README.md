# Интерактивный комикс для телевизора

**Открыть: https://vcmacte.github.io/interactive-comic/**


Телефон — «движок» (логика, звук, микрофон), телевизор — экран.
Картинка уходит на ТВ беспроводной трансляцией (Redmi Note 11 Pro 5G видеовыхода
по USB-C не имеет, только Miracast).

## Как запустить

### 1. Нужен HTTPS
Микрофон и установка PWA работают только в защищённом контексте.
`http://192.168.x.x:8080` **не подойдёт** — Chrome заблокирует микрофон.

Варианты: GitHub Pages, Cloudflare Pages, Netlify — любой даёт HTTPS бесплатно.
Для отладки на компьютере хватит `localhost` (он считается защищённым):

```
node serve.js          # http://localhost:8099
```

На `localhost` Service Worker намеренно не регистрируется и старые кэши
удаляются: иначе он отдаёт прошлую версию кода и правки не видны.
Это реальная ловушка — на ней уже один раз потерялась отладка.

### 2. На телефоне
1. Открыть адрес в **Chrome** (не в стандартном браузере MIUI).
2. Меню → **«Установить приложение»** и запускать потом с иконки.

   Это не косметика: во вкладке браузера на телевизор уезжают адресная строка
   и системные кнопки телефона. Убирает их только манифест установленного
   приложения (`display: fullscreen`). Если в меню стоит «Добавить на главный
   экран» вместо «Установить приложение» — получится обычная закладка, и
   строка останется. На стартовом экране в таком случае видна подсказка.
3. Включить «Не беспокоить», поставить телефон на зарядку.
4. Настройки → Подключение и общий доступ → **Трансляция** → выбрать телевизор.
5. Открыть иконку комикса, нажать «Начать историю», разрешить микрофон.

## Ориентация экрана

Манифест намеренно объявляет `"orientation": "any"`: ориентацию переключает
сам код. Выбор истории — портрет, сама история — альбом, кадр 16:9 иначе
не разложить. Если манифест навязывает альбом, портрет на главном экране
становится недоступен вовсе.

Главный экран **прокручивается**: содержимое центрирует внутренняя обёртка,
а не сам контейнер. При центрировании флексом снаружи обрезается верх списка,
и домотать до него нельзя — на телефоне в портрете так и получилось.

## Истории

На главном экране — список комиксов из `comics.json`, сами сценарии лежат
в `stories/`. Чтобы добавить новый: положить файл истории, собрать обложку
(`window.composeCover` в `tools/raster.html`) и дописать запись в каталог.

| Файл | О чём |
| ---- | ----- |
| `stories/minecraft.json` | «Первая ночь» по мотивам Minecraft, пять игр, обращение к зрителю по имени |
| `stories/hedgehog.json` | «Ёжик и лунная тропа», первая проба |

Имя зрителя задаётся полем `"viewer"`, в текстах пишется как `{{имя}}`
и подставляется один раз при загрузке истории.

## Структура

```
index.html      разметка: стартовый экран + кадр 16:9
css/style.css   крупная «плакатная» вёрстка под сжатие Miracast
js/app.js       движок: показ сцен, озвучка, выбор, подсказки
js/voice.js     синтез речи и распознавание, защита от эха
js/match.js     нечёткое сравнение ответа с ключевыми словами
js/tasks.js     генератор заданий: счёт до десяти и логика
js/stage.js     слои сцены и анимации входа, выхода, реакций
story.json      сценарий — здесь живёт вся история
tools/make-art.mjs  генератор фонов и персонажей
assets/bg/      слои локаций, assets/char/ — персонажи
tests-*.mjs     проверки: node tests-tasks.mjs и т.д.
```

## Формат сценария

```jsonc
"id_сцены": {
  "bg": { "sky": "assets/bg/sky.svg", "far": "...", "near": "..." },
  "cast": [ { "src": "assets/char/hedgehog.svg", "x": 40, "y": 27, "w": 16 } ],
  "text": "Текст на экране",
  "speak": "Что произносит рассказчик (по умолчанию = text)",
  "prompt": "Вопрос после текста",
  "choices": [
    { "label": "Кнопка", "keywords": ["слово"], "dir": "left", "next": "id_следующей" },
    { "label": "С репликой", "keywords": ["..."], "say": "Фраза перед переходом", "next": "id" },
    { "label": "Неверно", "keywords": ["..."], "hint": "Подсказка, остаёмся на сцене" }
  ]
}
```

Сцена без `choices` — финал, появится кнопка «Прочитать ещё раз».
Вариант с `hint` вместо `next` — подсказка и новая попытка на той же сцене.

### Сцена с генерируемым заданием

Вместо `choices` пишется вид задания — вопрос и варианты создаются на лету
при каждом заходе, поэтому сказку можно слушать много раз подряд:

```jsonc
"river": {
  "bg": { "sky": "...", "far": "...", "near": "assets/bg/near-river.svg" },
  "cast": [ { "src": "assets/char/beaver.svg", "x": 58, "y": 27, "w": 17 } ],
  "text": "У реки сидел бобёр: «Помоги мне сосчитать!»",
  "task": "math",      // math | logic | any
  "next": "gift"       // куда вести после верного ответа
}
```

Верный ответ ведёт на `next` со случайной похвалой, неверный остаётся
на сцене и даёт подсказку. Повтор по кнопке ⟲ не меняет задание —
новое сбило бы ребёнка на полуслове.

## Задания

`math` — счёт строго в пределах десяти: сложение, вычитание без перехода
через ноль, сравнение двух чисел, следующее число по порядку.
`logic` — того же уровня: что лишнее, скажи наоборот, продолжи чередование,
где живёт зверь.

Числа на экране — словами, голосом принимаются и слово, и цифра.
Существительные для счёта намеренно только мужского рода и неодушевлённые:
иначе получается «один ягода», а винительный падеж требует ещё двух наборов
окончаний ради того же самого задания.

Одно и то же задание не выпадает дважды подряд; неверные варианты берутся
рядом с правильным, а в логике — из той же категории, иначе ребёнок отсеивает
их не думая и задание пропадает зря.

## Голос

Голос выбирается не первый попавшийся, а по оценке: нейросетевые и Google
впереди встроенных «compact». Что досталось ролям — видно через `voiceReport()`.

**Рассказчик и герои говорят по-разному.** Разметка уже есть в самих текстах:
прямая речь в «ёлочках» произносится голосом персонажа, остальное —
рассказчиком (`ROLES` в `js/voice.js`). Если на устройстве несколько русских
голосов, роли получают разные; если один — расходятся по высоте и темпу.
На телевизоре через сжатие тонкая разница в тембре пропадает, а разница
в высоте слышна, поэтому разведены они заметно.

Какой голос у прямой речи, задаёт история полем `"voice"`: `hero` у Стива,
`friend` у лесных зверей. Вопрос к ребёнку всегда задаёт рассказчик — должно
быть слышно, что обращаются уже к нему.

Паузы: между предложениями, длиннее — на смене говорящего. Одним куском
получается диктор, читающий инструкцию.

### Если голоса в системе нет

Проверено в браузере телевизора (Tizen 8): русского голоса там не оказалось,
и роли оставались вообще без голоса — движок получал неизвестный ему язык
и молча ничего не произносил. Теперь берётся любой доступный голос: коряво,
но слышно. Если голосов нет совсем, озвучка отключается целиком, история идёт
без задержек, а на главном экране появляется предупреждение — иначе тишина
выглядит как поломка.

## Прослушивание ответа

Настройки вверху `js/app.js`: окно 30 секунд, четыре попытки, мягкая подсказка
после второй. Так сделано по жалобе из эксплуатации: посторонний шум
принимался за попытку ответить, и прослушивание обрывалось почти сразу.

Что изменено против первой версии:

* распознавание работает **непрерывно** и само перезапускается, пока окно не
  истекло. Движок на Android обрывается после паузы, и ребёнок, задумавшийся
  на три секунды, обнаруживал, что его уже не слушают;
* обрывки без настоящего слова (кашель, шуршание) не считаются попыткой;
* промах больше не обрывает прослушивание — считается и идёт дальше;
* подсказка произносится с выключенным микрофоном, иначе рассказчика слышит
  он сам: звук идёт на телевизор и возвращается в телефон.

## Что заложено в движке

* Микрофон включается **только после** того, как рассказчик замолчал — иначе
  звук с телевизора возвращается в микрофон и распознаётся как ответ.
* Два промаха подряд → рассказчик предлагает нажать кнопку. Ребёнок не застревает.
* Числа сопоставляются и словом, и цифрой («пять» = «5»).
* Опечатки распознавания прощаются по расстоянию Левенштейна: до 2 символов
  в длинных словах, 0 в коротких.
* Стрелки / Enter / цифры 1–9 — управление с клавиатуры или пульта, если
  приложение однажды переедет в браузер телевизора.
* Wake Lock держит экран включённым, Service Worker кэширует историю офлайн.
* Кнопки активны **всегда**: нажатие во время рассказа обрывает озвучку и идёт
  дальше. Заблокированные кнопки ребёнок считает сломанными и бьёт по ним сильнее.
* Озвучка не может уронить повествование: ни отсутствие русского голоса, ни
  отказ движка, ни потерянное событие `onend` не оставят историю висеть.
  Окончание реплики определяется опросом синтезатора, а не только событием.
* Запрос доступа к микрофону ограничен 20 секундами — если на диалог не нажали,
  история начнётся без голоса, а не замрёт на стартовом экране.

## Что проверено

Пройден весь граф сцен в браузере: обе ветки, обе сцены с заданиями,
неверный ответ с подсказкой, возврат в начало, финал и перезапуск.

```
node tests-match.mjs    нечёткое распознавание: пядь → Пять, 5 → Пять, к речке → к реке
node tests-tasks.mjs    1000 заданий: арифметика сходится, ответ ровно один,
                        счёт не выходит за десять, повторов подряд нет
node tests-voice.mjs    выбор голоса на разных наборах (Android, Windows, пусто)
```

**Не проверено вживую:** распознавание речи и синтез на самом телефоне,
а также качество картинки через трансляцию на телевизор — это нужно
прогнать на устройстве.

## Графика

Арт-направление — **ночные силуэты с лунной подсветкой**. Выбрано не случайно:
крупные плоские формы и высокий контраст переживают сжатие Miracast, тогда как
мягкая живопись на трансляции расплывается. Стиль ещё и легко описать одной
фразой нейросети, поэтому новые локации не выпадают из общего ряда.

Фоны и персонажи генерируются скриптом:

```
node tools/make-art.mjs
```

Случайность в нём детерминированная: один и тот же запуск даёт те же файлы,
иначе в истории правок нельзя было бы увидеть, что реально изменилось.

### Контракт на картинки

Сцена собрана из трёх слоёв плюс персонажи — они двигаются с разной скоростью,
и получается глубина вместо плоской подмены кадра:

| Слой    | Размер    | Что на нём                          |
| ------- | --------- | ----------------------------------- |
| `sky`   | 1920×1080 | градиент неба, луна, ореол          |
| `stars` | 1920×1080 | только звёзды, прозрачный           |
| `far`   | 1920×1080 | холмы, дальний лес, туман           |
| `near`  | 1920×1080 | земля, вода, кулисы по краям кадра  |
| персонаж | по силуэту | прозрачный фон, обрезан по контуру |

Две мерки, на которых всё держится:

- **Линия земли — 70% высоты кадра.** Ниже 74% картинку закрывает панель
  с текстом. Если ставить землю по нижнему краю, персонажи окажутся за панелью.
- **У файла персонажа `width`/`height` обязаны совпадать с `viewBox`.**
  Иначе браузер берёт пропорции из атрибутов, рисунок летербоксится внутри
  квадрата, и герой висит в воздухе на высоту пустого поля.

### Чем заменить на нейросетевую графику

Генерировать нужно теми же тремя слоями, а не одной картинкой: иначе
параллакс и анимации входа работать не будут. Персонажей — с прозрачным
фоном, обрезанными по силуэту.

## Анимации

Живёт в `js/stage.js`, вызывается из `app.js`.

| Событие            | Что происходит                                                     |
| ------------------ | ------------------------------------------------------------------ |
| вход в локацию     | слои выезжают с разной скоростью, персонажи появляются с подскоком |
| выход из локации   | слои уходят в сторону выбранного пути                              |
| выбор пути         | `"dir": "left" / "right" / "forward"` у варианта задаёт направление |
| верный ответ       | герой подпрыгивает, разлетаются искры                              |
| неверный ответ     | кнопка покачивается, герой удивлённо наклоняется                   |

Неверный ответ намеренно без красного и без резких движений: это не ошибка,
а приглашение попробовать ещё раз.

При системной настройке «меньше движения» анимации не отключаются, а сжимаются
почти в ноль — код остаётся один, а ребёнка с укачиванием не трясёт.

## Нейросетевая графика через локальную Easy Diffusion

На машине стоит Easy Diffusion (`D:\EasyDiffusion`, модель `deliberate_v2`,
RTX 3060). Работаем с ней **через HTTP-API на порту 9000, а не через браузер**:
картинки нужны пачками с одинаковыми настройками, руками в интерфейсе это
не повторить.

```
node tools/ed-generate.mjs --prompt "..." --out tools/out/x.png
node tools/paint-layers.mjs           # все слои разом
node tools/paint-layers.mjs sky       # только один
```

Запускать сам сервер (первый старт ~3 минуты — грузится модель в видеопамять,
дальше ~8 секунд на картинку):

```powershell
Start-Process cmd.exe -ArgumentList '/c','"D:\EasyDiffusion\Start Stable Diffusion UI.cmd"'
```

Из Git Bash через `cmd //c` **не запускается**: `cmd` читает первое слово
имени файла «Start» как свою встроенную команду и ищет файл «Stable».

### Почему img2img, а не генерация с нуля

Композиция берётся с наших векторных слоёв: линия земли на 70%, свободный
центр под персонажей, кулисы по краям. Генерация «с нуля» вернёт красивую
картинку с землёй где попало, и персонажи повиснут в воздухе.
`prompt_strength` подобрана по планам: небо 0.5, дальний план 0.45.

### Конвейер

1. `tools/raster.html` + `window.rasterInit` — SVG в растр 768×432.
   Браузер здесь единственный доступный растеризатор: ни ImageMagick,
   ни Inkscape, ни cairosvg на машине нет. Записывать файлы ему помогает
   эндпоинт `POST /save` в `serve.js` (только для локальной разработки).
2. `tools/paint-layers.mjs` — img2img + апскейл RealESRGAN ×4 до 3072×1728.
3. `window.composeLayer` — возврат прозрачности и сжатие до 1920×1080 в WebP.

**Звёзды вынесены из неба в отдельный слой.** Через img2img они ведут себя
одинаково плохо в обе стороны: яркую звезду в стороне от луны генератор
раздувает во второе светило, а если её приглушить — вымывает заодно и все
остальные, и небо становится пустым. Проверено на трёх прогонах. Отдельным
вектором звёзды ещё и сохраняют мерцание, которого растр дать не может.

Маска при сборке бывает двух видов:

- **силуэт из того же SVG** — для слоёв, сквозь которые должно быть видно небо;
- **мягкий вертикальный градиент** — для дальнего плана. Жёсткий силуэт срезает
  написанную дымку над лесом, и слой становится плоским набором тонких фигур.

### Что осталось векторным и почему

| Слой | Чем рисуется | Причина |
| ---- | ------------ | ------- |
| `sky` | нейросеть | мягкие градиенты и свечение луны — вектору недоступны |
| `stars` | вектор | через img2img звёзды либо раздуваются, либо вымываются; вектор ещё и мерцает |
| `far-*` | нейросеть | атмосферная дымка и глубина |
| `near-*` | вектор | нужен чёткий силуэт и лунный кант; живопись внутри почти чёрной фигуры ничего не добавляет |
| персонажи | вектор | Stable Diffusion не умеет прозрачный фон и не держит одного героя между кадрами |

У каждого зверя своя палитра (`FUR` в `tools/make-art.mjs`): ёжик тёплый
коричневый, сова буро-серая, бобёр рыжий. Одна палитра на всех давала
фиолетовый зверинец. Тона намеренно теплее и светлее фона — на синей ночи
холодный персонаж сливается с задником. Лунный кант при этом синий у всех:
это отсвет луны, а не цвет шерсти, и он связывает героев с фоном.

WebP вместо PNG обязателен: тот же комплект в PNG весит 8.7 МБ против 170 КБ,
а он целиком уходит в офлайн-кэш приложения.

Промежуточные файлы (`tools/init/`, `tools/painted/`) в приложение не попадают,
но их стоит держать: пересобрать слой из них — секунда, сгенерировать заново —
отдельный прогон.
