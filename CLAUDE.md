# Рабочие заметки по проекту

Интерактивный комикс для ребёнка семи лет. Телефон — движок (логика, звук,
микрофон), телевизор Samsung (QE55QN80FAUXUA, Tizen 8) — экран, картинка
уходит зеркалированием. Офлайновый PWA без сборщика и без зависимостей:
голые ES-модули, которые браузер грузит как есть.

Описание для человека — в `README.md`. Здесь техника: **один факт живёт
в одном файле**, поэтому из README всё это убрано, а не продублировано.

## Команды

```
node serve.js                  # http://localhost:8099 + POST /save для инструментов
node tests-tasks.mjs           # 1000 заданий: арифметика, ровно один ответ, предел счёта
node tests-match.mjs           # нечёткое распознавание ответа
node tests-voice.mjs           # выбор голоса на разных наборах
node tests-log.mjs             # разбор журнала на синтетических сессиях
node tests-listen.mjs          # цикл перезапуска микрофона на заглушке

node tools/check-voices.mjs    # у каждой реплики есть запись и роль совпадает
# http://localhost:8099/tools/listen.html — прослушать историю целиком
node tools/check-speech.mjs    # ПРАВИЛА ПИСЬМА ДЛЯ ОЗВУЧКИ — падает на нарушении
node tools/check-story.mjs     # устройство истории: граф, пути, длина, речь, крючки
node tools/check-stress-risk.mjs  # формы, у которых ударение не задать (--new, одна история)

node tools/log-report.mjs logs/comic-log-….json   # разбор журнала с телефона
```

Озвучка (подробности ниже):

```
node tools/tts/collect.mjs
node tools/tts/fish.mjs                                  # --dry, --force, --only=роль
# затем в tools/raster.html: window.transcodeAudio(ids)
node tools/tts/prune.mjs
```

Графика: `node tools/make-art-mc.mjs` (вектор), `node tools/paint-layers.mjs`
(покраска нейросетью).

Офлайн-кэш: `node tools/make-sw.mjs` (`--keep-version`, чтобы не поднимать
номер).

Тестов на движок нет — он проверяется прогоном истории в браузере.

## Как добавить комикс

Пропущенный шаг 8 — самая частая причина «на телевизоре старая версия»,
пропущенный шаг 6 — «в истории нет звука», пропущенный шаг 5 — дыра
в сюжете, которую потом найдёт ребёнок.

Сюжет очередного дня не придумывается с нуля: линия сериала, разбор уже
сделанных историй и заготовки будущих — в `STORYLINE.md`.

1. **Сценарий** — `stories/<id>.json`. Формат ниже. Имя зрителя задаётся
   полем `"viewer"`, в текстах пишется `{{имя}}` и подставляется один раз
   при загрузке. Если истории не нужно обращаться к ребёнку — поля нет.

   **Сейчас поля нет ни у одной истории, и лучше его не возвращать.** Причин
   две. По делу: озвучка идёт через чужой сервис, у бесплатного тарифа текст
   запроса может уйти в обучающий набор, и имени ребёнка там быть не должно.
   По существу: обращение без имени живее — «Выручай, главный по шерсти»,
   «Считай внимательно, главный счётчик», «Спасибо, друг по кирке». Имя
   в каждой второй реплике звучало однообразно, а такое обращение
   придумывается под сцену.

2. **Вектор** — новые слои и персонажи в `tools/make-art-mc.mjs` (или свой
   файл для другого стиля), затем `node tools/make-art-mc.mjs`. Контракт
   на картинки обязателен к соблюдению, см. ниже.

   Посмотреть глазами **до** покраски: композицию правит вектор, нейросеть
   её не исправит. Персонажи не должны налезать на постройки, а задуманное
   в кадре — на персонажей (жила алмазов однажды оказалась ровно за Стивом).

3. **Покраска** — три действия подряд, пропуск любого ломает следующее:
   - `window.rasterInit` в `tools/raster.html` — вектор в `tools/init/*.png`
     размером 768×432. Имя файла — путь слоя с дефисом вместо косой черты
     (`mc/far-river` → `mc-far-river.png`);
   - промпт слоя в `tools/paint-layers.mjs`, затем
     `node tools/paint-layers.mjs <слой> …` → `tools/painted/`;
   - `window.composeLayer` — вернуть прозрачность и сжать в WebP 1920×1080.
     Слой, закрывающий кадр целиком (небо, стена пещеры), маски не требует;
     сквозь дальний план должно быть видно небо — там `chromaKey` по цвету
     init-подложки `[10, 20, 48]`.

   У блочного мира `strength` **0.24**, а не 0.34: на большем значении
   `deliberate_v2` скругляет кубы в холмики, и узнаваемость пропадает.

4. **Обложка** — `window.composeCover` в `tools/raster.html` →
   `assets/covers/<id>.webp`. Она должна **отличаться от уже имеющихся
   с первого взгляда**: ребёнок выбирает по картинке, а не по подписи.
   Два дневных луга в каталоге неразличимы — берите другое время суток.

5. **Вычитка** — скилл `story-review` (`.claude/skills/story-review/`).
   Сюжетные дыры, недосказанности, нестыковки с прежними днями и слова,
   которых семилетний не знает. Три машинные сверки, потом **свежий взгляд
   субагентом**, и только потом правки — списком, а не сразу.

   Субагент здесь не украшение, а суть: тот, кто писал историю, её дыр
   не видит. В четырнадцатом дне автор пропустил «Живы!», выдуманное
   «дотаяла» и необъяснённый оберег — все три нашёл заказчик, то есть
   человек без авторского контекста. Субагенту поэтому **не дают** карточку
   дня из `STORYLINE.md`: прочитав замысел, он достроит его в голове
   и пропустит дыру так же, как автор. Прежние истории дать надо —
   ребёнок их слышал, канон сериала известен и ему.

6. **Озвучка** — четыре команды, порядок из раздела «Готовая озвучка»:
   `collect.mjs` → `fish.mjs` → `transcodeAudio` → `prune.mjs`.
   Последняя убирает записи, на которые больше никто не ссылается, и
   пересобирает `index.json`; она же скажет, если что-то осталось неозвученным.

   **До** озвучки прогнать две проверки, и обе обязательны — переозвучивать
   потом дороже, чем прочитать вывод:

   ```
   node tools/check-speech.mjs <история>       # падает на нарушении
   node tools/check-stress-risk.mjs <история>  # советует
   ```

   Первая держит правила письма для озвучки (двоеточие перед прямой речью,
   запретные слова) и **выходит с ненулевым кодом**, если нашла нарушение, —
   нарочно, чтобы её нельзя было проглядеть. Вторая показывает формы
   с плавающим ударением: у fish метки ударения нет, и «в гО́ре» вместо
   «в горЕ́» потом уже не исправить — только переписав фразу и переозвучив.
   Ребёнок такое замечает сразу.

   **Гонять их надо и ПОСЛЕ правки, а не только до.** Уходя от одной опасной
   формы, легко внести другую: замена «вдоль кладки» на «вдоль стены» внесла
   двусмысленное `стен+ы`/`ст+ены` и поймалась только повторным прогоном.

   После озвучки — **прослушать новые реплики**. Машинной сверки ударения
   на этом пути нет: она держалась на воспроизводимости Silero, а у fish
   один и тот же текст звучит каждый раз немного иначе.

7. **Каталог** — запись в `comics.json`: `id`, `title`, `subtitle`,
   `cover`, `story`. Запись кладётся **первой в свой сезон**: каталог —
   массив сезонов (`id`, `title`, `subtitle`, `cover`, `comics`), новый
   сезон первым. Главный экран показывает сначала сезоны, а серии — по
   нажатию на сезон. Обложка сезона — готовая обложка одной из его серий.
   Читатели каталога — `js/app.js`, `tools/check-story.mjs` и
   `tools/listen.html`. Все три разворачивают сезоны через
   `flatMap(s => s.comics)`, и порядок «от новой к старой» сохраняется.

8. **Кэш** — `node tools/make-sw.mjs`. Список собирается с диска и номер
   `CACHE` поднимается сам. Руками полтысячи путей не ведут: забытый файл
   не мешает разработке (там всё берётся из сети) — он ломает установленное
   приложение ровно тогда, когда сети нет.

9. **Проверка** — тесты, прогон истории целиком в браузере, затем боевой
   адрес. Что именно смотреть — в разделе «Что проверять».

## Формат сценария

```jsonc
"id_сцены": {
  "bg": { "sky": "...", "stars": "...", "far": "...", "near": "..." },
  "cast": [ { "src": "assets/mc/steve.svg", "x": 62, "y": 28, "w": 8 } ],
  "text": "Текст на экране",
  "speak": "Что произносит рассказчик (по умолчанию = text)",
  "prompt": "Вопрос после текста",
  "voice": "hero",
  "choices": [
    { "label": "Кнопка", "keywords": ["слово"], "dir": "left", "next": "id" },
    { "label": "С репликой", "keywords": ["..."], "say": "Фраза перед переходом",
      "voice": "beast", "next": "id" },
    { "label": "Неверно", "keywords": ["..."], "hint": "Подсказка, остаёмся на сцене" }
  ]
}
```

**Крючки между сериями** — два поля у истории целиком, рядом со `start`:

```jsonc
"hook": "колокол зазвонил сам",   // чем кончается, если это открытый вопрос
"closes": ["doubles"]             // чьи крючки эта история закрывает
```

Движок их не читает вовсе (`app.js` берёт `title`, `theme`, `voice`,
`start`, `scenes`), озвучка тоже — они не произносимые поля. Читает только
`check-story.mjs`: если у предыдущей истории в `comics.json` есть `hook`,
а текущая не называет её в `closes`, будет совет. Нить, оставленная
открытой нарочно, записывается в исключения с причиной — так помечен крест
на колоколе из одиннадцатого дня.

Сцена без `choices` — финал, появляются кнопки «Прочитать ещё раз» и
«Выбрать другую историю». Вариант с `hint` вместо `next` — подсказка и новая
попытка на той же сцене. `dir` (`left`/`right`/`forward`) задаёт, куда уедут
слои.

**Тупиковый выбор обязан что-то дать и сам вернуть в сюжет.** На поглаженной
корове это выяснилось в эксплуатации: выбор был, реакции не было, ребёнок
решал, что сломалось. Теперь у варианта есть `say` своим голосом и `next`
обратно в русло.

### Сцена с заданием

Вместо `choices` пишется задание — вопрос и варианты создаются при каждом
заходе, поэтому историю можно слушать много раз:

```jsonc
"wood": {
  "text": "Стив стукнул по дереву…",
  "task": { "kind": "math", "max": 10, "types": ["addition", "subtraction"] },
  "next": "craft"
}
```

`kind` — `math`, `logic` или `any`. `max` — предел счёта (5…20), растёт по
ходу истории. `types` — подвиды: `addition`, `subtraction`, `compare`,
`next`, `missing` у арифметики; `oddOneOut`, `opposite`, `pattern`, `home`,
`recipe` у логики. `topic` — предметная область (см. ниже).
Короткая запись `"task": "math"` тоже работает.

Верный ответ ведёт на `next` со случайной похвалой, неверный остаётся на
сцене и даёт подсказку. Повтор по кнопке ⟲ не меняет задание — новое сбило
бы ребёнка на полуслове.

**`types` и `topic` указывать обязательно.** Без них в сцене с крипером
у стены выпадала загадка про антоним к слову «медленно» — это нашли на детях.
Задание должно продолжать историю, а не падать в неё с потолка.

`types` сужает *вид* задачи, `topic` — предметный мир. Одного вида мало:
в шахте оставался вопрос про курицу, потому что вид подходил, а набор слов
был общий на всю тему. Области темы `minecraft`: `blocks`, `ore`, `fuel`,
`craft`, `animals`, `nether`, `end`, `raid`, `iron`, `outpost`, `siege`,
`doubles`, `after`, `woods`, `isle`.

**Метка области бывает только для логики.** Если все задания области —
логические, ей не нужны ни счётные слова, ни глагол потери: ни `oddOneOut`,
ни `pattern` не читают `countable` и `lostBy`. Так заведены `outpost`
одиннадцатого дня (три загадки и пять троек чередования), `siege`
двенадцатого (четыре загадки и шесть троек), `doubles` тринадцатого,
`after` четырнадцатого и `woods` пятнадцатого (у всех трёх четыре
загадки и шесть троек) —
всё дописано **в конец** массивов,
и ни одной переозвученной записи. Повод был не в экономии:
логика рейда исчерпана, у `oddOneOut` там шесть троек (восемнадцать
вопросов), и дни 8 и 10 выбрали из них по десять, а рецептов у рейда
всего три, и они звучали в восьмом дне.

У таких областей **`math`, `home` и `recipe` брать нельзя** — ровно по той
же причине, что у `iron` ниже: `narrow` молча откатится на общий набор.

У области `iron` (железо и ритуал девятого дня) размечены только
`countable`, `oddOneOut` и `recipes`. Чередований и домов у неё нет,
поэтому `pattern` и `home` с ней брать **нельзя**: `narrow` молча
откатится на общий набор, и в зале ритуала выпадет «свинья, корова,
свинья, корова».

## Задания

`js/tasks.js`. Уровень намеренно низкий: счёт до десяти-двадцати и логика
первого класса. Задача — поддержать повествование, а не проверить знания.

Вычитание держится в пределах десяти даже там, где сложение идёт до двадцати:
переход через десяток в обратную сторону первокласснику даётся заметно хуже.

Предметный мир задаёт тема (`"theme"` у истории): у всех историй это
`minecraft`. Тема `forest` осталась в `js/tasks.js` без истории: она —
значение по умолчанию у `makeTask` и на ней стоят проверки `tests-tasks.mjs`,
которые ловят, что генератор не тащит в тему данные, которых у неё нет. Тема — это наборы `countable`, `oddOneOut`, `opposites`,
`patterns`, `homes`, `recipes` и глагол потери (`lost`).

Записи помечены полем `topic`, и сцена сужает набор до своей области
(`narrow` в `js/tasks.js`). Запись без метки в сужение не попадает;
если по области не нашлось ничего, берётся общий набор — опечатка
в сценарии не должна оставить сцену без задания. Антонимы метками не
размечены: это пары слов, у них нет места в сюжете. Чередования
размечаются с шестого дня — тройка пишется как `{ seq, topic }`, а
неразмеченная остаётся простым массивом (менять старые записи ради
единообразия нельзя: от этого переписался бы готовый пул). Поводом стала
загадка «свинья, корова, свинья, корова» в зале с рамкой портала: вид
задания подходил, а слова были общие на всю тему.

**У логических видов `max` на вопрос не влияет, но входит в ключ пула.**
Генераторы логики предел счёта не читают вовсе, а ключ считается как
`тема|вид|max|область`. Поэтому смена `max` — законный способ завести виду
собственный ключ, когда в прежнем он встал бы **перед** уже озвученными
видами и переписал бы их. На шестом дне так разведены две сцены из пяти.

**`onlyTopic` у записи** означает «живёт только в своей области»: в общий
набор — тот, что получает сцена без `topic`, и тот, на который падает
откат, — она не попадает. Так помечен Нижний мир, а с шестого дня — книги
библиотеки. Причина двойная: по смыслу — стержень и кварц на лугу первого
дня взялись бы из ниоткуда; по делу — общий набор уже озвучен целиком, и
любое его расширение переписало бы пул дня первого, а это около трёхсот
осиротевших записей. То есть метка годится любой записи, которую нельзя
пускать в общий набор без переозвучки.
Поэтому после правки наборов темы смотреть не на размер диффа, а на то,
осталась ли каждая прежняя запись на своём месте. Быстрая проверка —
`git diff -U0 stories/tasks-pool.json | grep '^-[^-]'`: пусто значит
«всё хорошо наверняка». Но **минус-строки сами по себе ещё не беда**: как
только вид дописывается в конец уже озвученного ключа, записи вставляются
в середину файла, и построчный дифф перекраивает соседние блоки, ничего
не меняя по сути. Так было на десятом дне. Тогда надо сверять не строки,
а содержимое — старый пул из `git show HEAD:stories/tasks-pool.json` рядом
с новым, ключ за ключом, запись за записью по `question` и `audio`.
Окончательная же проверка одна и та же всегда: из `tools/tts/manifest.json`
не пропало ни одного идентификатора, а `prune.mjs` удалил ноль.

Глагол потери тоже зависит от области (`lostBy`): у печки уголь **сгорает**,
а не «взрывается крипером». Без этого вычитание в сцене с печкой звучало
нелепо.

Обратная сторона того же правила: **глагол подбирается ко всем словам
области сразу, а не к удобному**. У Края `lostBy.end` — «погасло», и
поэтому в его `countable` лежат только «кристалл» и «огонёк»: «столб»
туда не попал, иначе выпало бы «погасло три столба». Сцена считает
огоньки **на** столбах — текст написан под набор слов, а не наоборот.

Генератор может потребовать данных, которых у темы нет (`needs` у `recipe`).
Тогда он для этой темы просто не предлагается — иначе `kind: "logic"`
у леса однажды вытянул бы рецепты, которых там не существует.

**Существительные для счёта — только мужского рода и неодушевлённые.** Иначе
получается «один доска», а винительный падеж требует ещё двух наборов
окончаний ради того же задания. Это ограничение, а не стиль: добавлять
«шерсть» или «ягоду» в `countable` нельзя, для таких вещей задача делается
логической.

Числа на экране словами, голосом принимаются и слово, и цифра. Одно задание
не выпадает дважды подряд. Неверные варианты берутся рядом с правильным,
а в логике — из той же категории: иначе ребёнок отсеивает их не думая.

### Широкий разброс: `"spread": "wide"`

Тесная тройка ±1/±2 подбирается позицией: числа часто идут подряд, и верное
стоит ровно посередине, а у границы предела оба неверных встают с одной
стороны — и верное всегда крайнее. Поле сцены включает другой генератор
вариантов: одна **ловушка от типичной ошибки** (результат не той операции —
у сложения разность, у вычитания сумма, у «сколько прибавилось» само
«стало») плюс число на расстоянии 2–5; между любыми двумя вариантами
не меньше двух, поэтому тройки подряд не бывает.

Почему флагом, а не заменой `numberChoices`: пул озвучки собирается тем же
генератором, и правка общего поведения переписала бы вопросы всех прежних
ключей вместе с готовыми записями. Флаг входит **пятым сегментом** в ключ
пула (`minecraft|math|20|raid|wide`), и только при `wide` — без него ключ
остаётся прежней строкой байт в байт. Считается это в двух местах сразу,
как и сам ключ: `js/tasks.js` и `tools/tts/collect.mjs`.

Генератор `opposite` править нельзя, даже если тройка кнопок читается
двусмысленно («день» → «темнота»): дистракторы он берёт из других пар,
и пара-дублёр превращается в кнопку, которую ребёнок вправе счесть верной.
К тому же вопросы этого вида уже озвучены, и правка кода переписала бы их
все. Чинится это списком слов `opposites` у нужной темы, а не кодом.

## Голоса и роли

`js/voice.js`. Роли: `narrator`, `hero`, `friend`, `kid` (свинолюд, не ребёнок),
`villain` (дракон), `beast` (корова и эхо колодца), `ally` (Алекс),
`golem` (Железный голем) и `trickster` (иллюзионер).
Прямая речь в «ёлочках» произносится голосом персонажа, остальное —
рассказчиком.

`friend` — одна роль на двоих: житель в `nether`, `wall`, `outpost` и
библиотекарь в `stronghold`, `golem`. Оба деревенские, оба «Хм-хм!», голос
у них общий намеренно.

`kid` — свинолюд, и с четырнадцатого дня он **сквозная пасхалка**: выходит
редко, всегда тупиковым выбором, и реплика у него всегда начинается
с «Хрю!». Правила приёма — в `STORYLINE.md`, раздел «Пасхалка: свинолюд»;
здесь только то, что из них следует для техники. На Silero `kid` и `ally`
делят диктора `kseniya` и разведены темпом (1.08 против 0.97) — тринадцать
дней они не встречались в одной истории, а в четырнадцатом встретились
(`tracks` и соседние сцены «Утра после рейда»). У fish модели у них разные,
так что на основном пути это ничего не изменило; если корпус когда-нибудь
вернётся на Silero, эти две роли надо слушать рядом.

**Освободившуюся роль новому персонажу не отдавать.** Иллюзионер
тринадцатого дня сперва получил `villain` — роль считалась свободной,
раз дракон больше не выходит. На прослушивании это поймали сразу:
«голос надо другой, этот был у дракона». Голос у fish узнаётся, и шесть
дней разницы ребёнка не обманывают. Переиспользование ролей — наследие
Silero, где дикторов было пять на девять; у fish потолка нет, и новому
персонажу заводится **своя** роль (`trickster`). Проверять это надо
раскладкой `node tools/tts/fish.mjs --dry`: она печатает реплики по ролям,
и чужой голос виден там ещё до синтеза.

**У волка нет голоса вовсе, и роли `wolf` больше нет.** Его звуки
описывает рассказчик прозой, без «ёлочек»: «сел ровно и завыл — тихо
и протяжно», «коротко тявкнул», «тявкнул дважды и пошёл впереди всех».

Роль была и работала иначе: скулёж и лай стояли в «ёлочках» голосом `wolf`,
как «Мууу» у коровы. Убрана после прослушивания — ни один из шести голосов
библиотеки по запросу «волк» не звучит зверем, все читают «у-у-у» человеком.
Пробы снимались `tools/tts/try-voice.mjs`, и это тот случай, когда чинить
нечем: у fish нет звука, который не был бы речью.

Корова и эхо (`beast`) при этом остались — «Мууу» человеческим голосом
проходит как шутка, а вой не проходит.

Какой голос у роли на основном пути — в `tools/tts/fish-voices.json`:
там своя модель на каждую из девяти ролей, и потолка больше нет. Роль,
которой в этом файле нет, просто не озвучивается: `fish.mjs` скажет об этом
и не станет гадать — так и устроен отказ от голоса волка.

**Подобрать голос можно только ухом**, и для этого есть
`node tools/tts/try-voice.mjs <что искать> "<реплика>" ["<ещё реплика>"]`:
он берёт из библиотеки шесть голосов и кладёт пробы на страницу
`tools/voice-try/index.html`. Выбирает человек. Ниже —
про прежний путь, Silero, где потолок был и никуда не денется.

Свободных дикторов у Silero v3 нет: их пять, и все заняты первым сезоном.
Новые роли разведены **темпом** в `RATE_SCALE` (`tools/tts/render.py`) —
тем же приёмом, которым там разведены `villain` и `beast`. Алекс звучит
той же `kseniya`, что и свинолюд, но медленнее (0.97 против 1.08).
Тринадцать дней они не встречались ни разу — свинолюд жил в Нижнем
мире, — а в четырнадцатом он вышел пасхалкой в деревне, и в одной
истории они уже оказались: на этом пути их различал бы только темп.
Голем — `eugene` на 0.80, ниже
и медленнее зверя, волк — тот же `eugene` на 0.76, ниже всех. Добавление
роли **ничего не переозвучивает**: имя файла считается от `роль|текст`,
а у старых реплик роль не менялась.

Какой голос у персонажа, задаёт `"voice"` — у истории целиком,
у сцены или у отдельного варианта выбора.

Голос задаётся на сцену целиком, поэтому два персонажа в одной сцене разными
голосами звучать не могут — реплики разносятся по сценам. Исключение сделано
для варианта выбора: корова мычит ролью `beast`, иначе мычала бы голосом
Стива.

**Роль реплики варианта считается в двух местах, и они обязаны совпадать.**
Порядок один: свой `voice` варианта, иначе голос сцены, иначе голос истории —
так в `js/app.js` (`choice.voice ?? voiceOf(state.scene)`) и так же должно
быть в `tools/tts/collect.mjs`. Пока коллектор брал голос истории, у сцены
со своим голосом запись искалась под чужим именем и не находилась вовсе:
в девятом дне Алекс отвечала голосом Стива, а голем уходил в браузерный
синтез. Симптом коварный — не тишина, а *не тот голос*.

**Авторская ремарка не должна стоять внутри «ёлочек».** Разбиение простое:
всё, что в кавычках, читает персонаж. Поэтому «Насмотрелись, — тихо сказала
Алекс. — Побежали» произносится голосом Алекс целиком, вместе со словами
«тихо сказала Алекс», и звучит это нелепо. Ремарка выносится перед
кавычками: «Алекс сказала совсем тихо: „Насмотрелись…“».

По той же причине реплику нельзя рвать многоточием, если в тексте написано,
что герой помолчал: пауза слышна только там, где между двумя кавычками стоит
фраза рассказчика. «…не выстоять». Она помолчала. «Но я знаю, кого…» —
вот это звучит паузой, а многоточие внутри одной реплики — нет.

Вопрос к ребёнку **всегда** задаёт рассказчик — должно быть слышно, что
обращаются уже к нему.

Браузерный синтез выбирает голос по оценке (нейросетевые и Google впереди
встроенных «compact»), что досталось ролям — через `voiceReport()`. Если
русского голоса нет, берётся любой: коряво, но слышно. Если голосов нет
совсем, озвучка отключается, история идёт без задержек, а на главном экране
появляется предупреждение — иначе тишина выглядит как поломка.

### Озвучка вариантов: всё или ничего

Варианты читаются либо все, либо ни один — смотря, названы ли они в самом
вопросе (проверка `allNamed` в `js/app.js`). Половинчатый случай был хуже
обоих: у задания «что дальше: блок, факел, блок, факел» озвучивался
единственный вариант, которого в вопросе нет, — то есть прямая подсказка.

Формулируя новый вид задания, выбирай сознательно: либо вопрос перечисляет
все варианты, либо ни одного.

Правило живёт **в одном месте** — `spokenLabels` в `tools/tts/utterances.mjs`;
оттуда его берут и обход сцены, и коллектор. Пока коллектор знал правило
по-своему и озвучивал подписи всегда, в корпусе лежало **110 записей,
которых движок не проигрывает никогда**: полмегабайта мёртвого груза
в офлайн-кэше телевизора. Нашлось это на код-ревью, а не на слух, — такую
лишнюю запись не слышно по определению.

## Готовая озвучка

В браузере телевизора русского голоса нет вовсе, и история шла в тишине.
Поэтому реплики начитаны заранее и лежат файлами. Браузерный синтез остался
запасным путём на случай, если текст поменяли, а озвучку не пересобрали.

Читает их **fish.audio** (`tools/tts/fish.mjs`), модель `s2.1-pro-free`.
До этого читала Silero (`tools/tts/render.py`), и тот путь никуда не делся —
он локальный, бесплатный и работает без сети. Но голос у fish живее, а
главное — у неё **нет потолка в пять дикторов**: роль получает свой голос
из библиотеки, а не разводится темпом с чужим. Голоса ролей — в
`tools/tts/fish-voices.json`, выбраны прослушиванием одних и тех же реплик
корпуса подряд.

**Смешивать два движка внутри корпуса нельзя.** Имя файла считается от
`роль|текст` и про движок ничего не знает, поэтому реплика, озвученная
Silero, спокойно ляжет рядом с репликой от fish — и ребёнок услышит, как
рассказчик меняет голос посреди сцены. Если переозвучивается часть, она
должна идти тем же движком, что и остальное.

Платить за это пришлось двумя вещами, и обе стоит помнить:

* **ударением управлять нечем.** Метку `+` fish не слушает, фонемные теги
  у неё есть только для английского, китайского и японского — проверено
  замером. Поэтому `accents.json` на этот путь не действует вовсе, а
  неверно прочитанное слово лечится не правилом, а другим словом
  в сценарии (см. «Писать так, чтобы ударение было одно»);
* **вывод невоспроизводим.** Параметра `seed` у них нет: тот же текст
  дважды даёт разную длительность — у нас выходило до 29 % разницы.
  Поэтому готовые WAV не переозвучиваются без `--force`: лишний прогон
  меняет темп реплики, и она начинает выбиваться из соседних.

**Чем чинить то, что fish прочла неверно.** Прямого рычага нет, но
`fish-say-as.json` подменяет текст на время синтеза — имя файла считается
от чистого текста сценария, поэтому правило перезаписывает только задетые
записи. Правило бывает на всю реплику (`from` + `role`) или на слово
во всех репликах (`word`, границы слова проверяются: «замок» не задевает
«замочек»). Подменять приходится само звучание: заглавная ударная гласная,
удвоенная гласная, указание в квадратных скобках. **Каждое такое правило
надо слушать** — работают они через раз. Если ни одно не помогло, слово
меняется в сценарии, и это нормальный исход, а не поражение.

Переозвучить именно задетые реплики: удалить их WAV из `tools/tts/wav/`
и прогнать `fish.mjs` без `--force` — готовые он пропустит.

### Эмоции: восклицательный знак, а не теги

Жалоба была прямая: происходит важное, а герой говорит ровным голосом.
Перебрали **все** рычаги, какие у fish есть, и записали результат, чтобы
не перебирать снова.

| что пробовали | исход |
| --- | --- |
| `[кричит]`, `[шепчет]`, `[встревоженно]`, `[устало]` | не слышно |
| `<whisper>`, `<shout>`, `<angry>`, `<excited>` | не слышно |
| их же английский образец `I'm fine. Really. <whisper>Go on without me.</whisper>` | **тоже не слышно** |
| `temperature`/`top_p` 0.9 вместо 0.5/0.7 | не слышно |
| **восклицательный знак** | **работает** |

Каждый замер шёл с контрольным дублем на ту же фразу — у fish нет `seed`,
и без контроля разброс между дублями не отличить от действия тега.
Английский образец взят нарочно: он отличает «тег не работает вовсе» от
«не работает по-русски». Не работает вовсе. Теги при этом вслух не
читаются — модель их просто проглатывает, длительность не меняется ни
на долю секунды.

Поэтому **поля `mood` у сцены нет и заводить его незачем**, а эмоция
пишется текстом:

* **восклицательный знак в эмоциональных местах повествования** — не
  только в прямой речи. Это даёт голосу больше, чем любой тег;
* ремарка рассказчика **перед** кавычками: «крикнул», «сказал совсем
  тихо», «загудел на весь пролом»;
* короткая рубленая фраза вместо длинной.

### Слова, которых ребёнок не знает

Проверяется только ухом и только на ребёнке: ни тесты, ни `check-voices`
этого не ловят. Найденное на прослушивании — и то, чем заменено:

| не писать | писать |
| --- | --- |
| кладка | стена |
| засечка, скол | царапина, вмятина, след |
| зиял, наскоро | «так и остался», «закидал блоками» |
| штабель | горка |
| ведро (как железная вещь) | ножницы |
| кладку вёл, погнуто | стену вёл, кривое |

**В `keywords` эти слова оставлять можно и нужно** — они не озвучиваются,
а распознаванию лишний синоним не мешает. Убирать их надо только из
произносимых полей: `text`, `speak`, `prompt`, `say`, `hint`, `label`,
`question`, а ещё из наборов `js/tasks.js`, откуда одно слово расходится
в десятки вопросов пула.

**Прозы здесь мало, поэтому список проверяется машинно.** В граблях было
записано, что «кладка» заменена в днях 9–11, — и этого не хватило: слово
всё равно ушло в двенадцатый день восемь раз, а в десятом оно вдобавок
никуда и не девалось. Теперь список живёт в `tools/tts/speech-rules.json`,
а сверяет его `node tools/check-speech.mjs`, и она **падает** на находке.

Новое слово добавляется туда же — одной строкой `{ stem, instead, why }`.
Два подвоха, на обоих уже обожглись:

* **корень берите коротким.** Сперва стояло `засечк` — и оно пропустило
  «засеч**е**к» в финале двенадцатого дня, потому что в родительном
  множественного гласная беглая. Нашлось ухом, а не проверкой;
* **слишком короткий корень ловит лишнее:** `скол` находит «сколько»
  и «сколотил». Для таких есть поле `allow`.

Проверка смотрит только произносимые поля, поэтому «кладка» в `keywords`
десятого дня её не беспокоит — и правильно.

**Двоеточия перед прямой речью быть не должно.** Разбиение режет реплику
по «ёлочкам», и кусок рассказчика кончается тем знаком, что стоял перед
кавычками. Двоеточие — знак продолжения: модель читает с ним фразу так,
будто она не кончилась, и вся подводка звучит ровно, даже когда дальше
крик. Точку туда не дописывает и `finished()` в `fish.mjs` — знак формально
уже есть.

Поэтому вместо двоеточия ставится знак **по смыслу и по тому, как сказано**:

| подводка | знак |
| --- | --- |
| «крикнула сверху», «загудел на весь пролом», «велел не сбиваться» | `!` |
| «сказала глухо», «сказала тихо», «сказала сквозь зубы», «проверял себя вслух» | `.` |
| «спросил», «обернулся к тебе» | `?` |

Это правило применено **ко всем историям, какие были на тот день**, —
двенадцати: 42 двоеточия
заменены, из них шесть — на восклицание, там где в прозе прямо сказано
«крикнул» или «позвал». Держит его `node tools/check-speech.mjs`, и она
падает, если двоеточие вернётся.

Мера нужна и здесь: рассказчик, восклицающий всю дорогу, хуже ровного.
Знак ставится там, где бьют, ломают и кричат, а вопрос ребёнку и финал
остаются спокойными. Это тот же приём, что с ударением: чиним словом,
а не костылём. Исключение одно — `[скулит]` у волка: оно лечит не эмоцию,
а чтение «у-у-у» по буквам.

**Точка в конце реплики дописывается при синтезе.** Прямая речь кончается
без знака: точка стоит снаружи «ёлочек» и в запись не попадает, а модель
читает такой текст с интонацией продолжения — фраза звучит оборванной
на полуслове. Дописывает её `finished()` в `fish.mjs`, на самом последнем
шаге: текст сценария, экран и **идентификатор** при этом не меняются —
имя файла считается от «роль|текст» в двух местах сразу (`js/audio.js`
и `collect.mjs`), и правка текста в любом из них развела бы их между собой.
Под правило не попадает текст из одного слова: подписи кнопок («Шесть»,
«Нить», «Осмотреться») предложением никто не писал. Правило общее, но
прежние записи оно само не чинит — звук меняется только при переозвучке;
в «Аванпосте» так переозвучены 11 реплик, остальные истории остались
как есть.

Бесплатный доступ к модели заявлен до **30 ноября 2026**; на платном те же
голоса стоят $15 за миллион байт текста — весь наш корпус около двух
долларов. У бесплатного тарифа запросы могут идти на обучение их моделей,
и именно поэтому **имени ребёнка в текстах нет нигде**: обращение к зрителю
везде безымянное.

Файл находится **по содержимому**: FNV-1a от `роль|текст` даёт имя файла.
Поэтому ни сцены, ни задания нигде не перечисляются — совпал текст, нашлась
запись. Расчёт продублирован в `js/audio.js` и `tools/tts/collect.mjs`;
менять его можно только в двух местах сразу.

Задания генерируются на лету, озвучить их «как есть» нельзя. Поэтому
генератор прогоняется заранее и даёт пул готовых вопросов — `PER_TYPE = 5`
на каждый вид, поровну (раньше вид выбирался случайно, и при ограничении
сцены одним видом вариантов оставалось вчетверо меньше, чем кажется).
Набор **воспроизводим**: `Math.random` подменяется на генератор с постоянным
семенем, иначе каждая пересборка давала бы новый пул и вся озвучка
устаревала от правки одной строки.

**Генерируется по-прежнему десять на вид (`GEN_PER_TYPE`), в пул идут первые
пять.** До 30.10.2026 в пуле было десять; заказчик попросил пять. Просто
заменить 10 на 5 нельзя: виды одного ключа идут одним потоком чисел, и
второй вид ключа получил бы другие вопросы вместе с новой озвучкой. При
срезе каждый оставшийся вопрос совпадает с прежним байт в байт: из 634 задач
осталось 330, новых записей ноль, а лишние удалил `prune.mjs`.

Озвучиваются **только те виды, которые сцены действительно просят**: ключ
пула собирает объединение `types` всех сцен, которые к нему обращаются.
Раньше набирались все виды подряд, и четыре пятых записей никогда не
звучали — просто лежали в офлайн-кэше. Сцена без `types` означает «любой»,
и тогда сужать нельзя.

Семя случайности считается **от ключа пула**, а не одно на весь прогон.
С общим семенем новая история сдвигала поток чисел и переписывала вопросы
всех прежних сцен, а с ними и всю их озвучку. Теперь добавление комикса
не трогает ни одного готового файла.

Это про **добавление истории**. Правка самой темы в `js/tasks.js` — новое
слово в `countable`, лишний рецепт, ещё одна загадка — переписывает пул тех
ключей, куда этот набор входит, и прежние записи к ним осиротевают: их
удалит `prune.mjs`, а новые придётся озвучить. На третьем дне так ушли
тридцать записей. Ничего страшного, но прогон озвучки после этого
обязателен, иначе сцены старых историй останутся без звука.

Сейчас: 52 ключа пула, 355 задач, 1235 записей, 21.9 МБ — шестнадцать историй,
все озвучены fish.audio.

### Как пересобрать

```
node tools/tts/collect.mjs                               # манифест + пул
node tools/tts/fish.mjs                                  # fish.audio -> WAV
# затем в tools/raster.html: window.transcodeAudio(ids)  # WAV -> MP3 40 кбит/с
node tools/tts/prune.mjs                                 # чистка + index.json
```

`fish.mjs` печатает список «есть WAV, нет MP3» в `tools/tts/fish-pending.json` —
его и надо отдать `transcodeAudio`. **Но при смене движка этот список
бесполезен**: MP3 у всех реплик уже есть, просто они от прежнего голоса.
Тогда в `transcodeAudio` отдаётся весь манифест целиком, а WAV-ы прежнего
движка перед прогоном убираются — иначе `fish.mjs` их пропустит как готовые. `prune.mjs --dry` покажет, что будет
удалено, ничего не трогая.

Готовые WAV пропускаются, прогон можно прерывать и повторять; `--force`
переозвучивает поверх, `--only=роль` берёт одну роль, `--dry` только считает
и показывает цену. Ключ — переменная `FISH_API_KEY` или файл
`tools/tts/fish-key.txt` (он в `.gitignore`).

**Прежний путь, Silero.** Остался на месте и работает:

```
"D:/EasyDiffusion/installer_files/env/python.exe" tools/tts/render.py
```

Голоса ролям там назначаются в `SPEAKERS`, темп — в `RATE_SCALE` (Silero
скоростью не управляет, поэтому меняется частота воспроизведения).
Дикторов у неё пять на десять ролей, поэтому новые роли разведены темпом.
Годится, если нет сети или кончился бесплатный доступ к fish, — но тогда
переозвучивать надо **весь** корпус, а не часть.

### Ударения: только у Silero

Всё в этом подразделе относится к `render.py`, то есть к **прежнему** пути.
У fish.audio управления ударением нет вовсе — там работает другое средство,
«Писать так, чтобы ударение было одно» ниже. Файл `accents.json` при этом
не выброшен: он нужен, если корпус придётся переозвучить Silero.

Silero ставит ударение сама и на омографах ошибается: «в горе» читала как
«г+оре», хотя речь про гору с алмазами. Поправки живут в
`tools/tts/accents.json` — знак `+` **перед** ударной гласной.

Тем же файлом чинится **звучание, а не только ударение**: правило — это
обычная замена текста, поэтому заимствованное слово можно переписать так,
как оно читается. «Тотем» модель произносит с мягким «те», а надо твёрдое:
правило `тотем → тот+эм` (и по одному на каждую форму — границы слова
проверяются, так что `тотем` не задевает `тотема`). Ударение при этом
обязано остаться на прежнем слоге, иначе правило чинит одно и ломает
другое.

Правила применяются **только при озвучке**. Имя файла считается от чистого
текста сценария, поэтому новое правило перезаписывает ровно те записи,
которых касается, и не трогает ни одной посторонней:

```
python tools/tts/render.py --restress    # переозвучить задетые реплики
```

**Проверять ударение можно не слушая.** Синтезируем реплику дважды — как
есть и с явной меткой; совпали байт в байт — модель и так ставила ударение
туда же. На этом стоят два инструмента:

```
python tools/tts/check-accents.py   # какие правила работают, какие лишние
python tools/tts/audit-accents.py   # ударение Silero в каждом слове корпуса
```

`check-accents.py` отдельно показывает устаревшие правила — те, что больше
ни к чему в манифесте не подходят. Правило, которое ничего не меняет,
из файла убирается: оно только маскирует будущие расхождения.

**Сначала словарь, потом правило.** `audit-accents.py` показывает, куда
ставит ударение модель, но не говорит, права ли она. На «тотеме» это стоило
прогона: ударение показалось странным, правило увело его на первый слог —
а верно как раз тот+ем, и правило испортило четырнадцать готовых записей.
Если слово заимствованное или редкое, проверить его в словаре прежде, чем
писать правило; отменять потом дороже, чем не заводить.

Правило пишется **фразой только тогда, когда слово омограф** («в горе»,
«дом стоит»). Если ударение у слова одно и то же везде, правило задаётся
самим словом: «простая кирка» закрывала одну реплику из семи — остальные
шесть живут в заданиях («что здесь лишнее: рыба, осьминог или кирка?»),
и там ребёнок слышал к+ирку. Границы слова `accents.py` проверяет сам,
так что «кирка» не задевает «кирку» и «киркой».

Обратная сторона тех же границ слова: **правило словом не покрывает падежные
формы**. Рядом с «б+ерег» пришлось отдельно завести «по б+ерегу» — одним
словом его не задать, потому что «берегу» ещё и глагол «я берегу».

### Писать так, чтобы ударение было одно

`accents.json` работает только у Silero: правило применяется при озвучке,
и запись выходит верной. У озвучки со стороны такого рычага может не быть
вовсе — у fish.audio метка ударения не слушается, а фонемные теги есть
только для английского, китайского и японского. Тогда единственное
управление — **не употреблять форму, у которой чтений два**.

Случаев два, и лечатся они по-разному. Фразовая двусмысленность снимается
перефразировкой; однословная («сопел», «далеко», «ему») — нет: ударение
у слова одно-единственное, модель просто ошибается, уточнять там нечего,
и такое слово можно только заменить, узнав о нём на слух.

**Проза по этому правилу уже переписана** — вся. Разом её переписали
по одиннадцати историям, а дни двенадцатый и тринадцатый писались
по правилу сразу. Было 63 двусмысленных места, осталось 4, и все четыре оставлены
сознательно (ниже); `--new` покажет 6 — к ним добавляются `далеко` и
`свои` из однословных. Заодно в `accents.json` осталось 11 правил вместо
56: фразовые больше ни к чему не подходят, потому что самих фраз в корпусе
нет, а вместе с наборами заданий ушли `доски`, `кирка` и `тотем`. Знание
не потерялось, а переехало — из «чиним при озвучке» в «не пишем вовсе»,
то есть в `stress-risk.json`. Оставшиеся 11 — только однословные ошибки
модели плюс `в Краю`.

Две трети фразовых — **одна и та же ловушка**: родительный или дательный
единственного числа у существительного, у которого именительный
множественного пишется так же («у края леса», «у реки», «на полу»,
«раньше колокола»). Снимается уменьшительным («у речки», «у стенки»),
именительным («раньше, чем ударил колокол») или другим словом («на земле»).
Отдельной строкой — глагол «стоит»: за пять правил из 39 отвечает он один,
и в сценариях его лучше не писать вовсе.

Список форм — `tools/tts/stress-risk.json`, поиск по текстам —
`node tools/check-stress-risk.mjs` (`--new` покажет только то, что не
разобрано для Silero). Проверка **советует**: двусмысленная форма не дефект,
половина находок безобидна, и решает тот, кто слушал. Уводить надо
**в простое слово, а не в редкое**: «у края леса» → «у леса», а не
«у лесной кромки» — иначе чиним ударение и ломаем понятность, как было
с «кладкой».

Наибольший вес — не в прозе, а в **наборах слов `js/tasks.js`**: одно слово
размножается в десятки вопросов пула, а фраза сценария живёт в одной сцене.
Шесть слов («доски», «кирка», «далеко», «тотем», «сама она», «из Края»)
давали 36 находок из 42 по всему пулу — **это уже сделано** вместе
с переходом на fish, и проверка по пулу теперь показывает ноль. «Доски»
заменены на «брёвна» (буква ё всегда ударная, прочесть иначе нельзя),
«кирка» в списках слов — на другие инструменты (в падежах «кирку»,
«киркой» ловушки нет, поэтому рецепт остался), «тотем» — на «плащ».
Правка наборов переписывает пул и осиротяет записи, поэтому делать её
имеет смысл **в один проход с полной переозвучкой**, а не отдельно.

**После перехода на fish эти 11 правил бездействуют.** `accents.json` читает
только `render.py`, поэтому слова, которые Silero произносила неверно,
теперь ничем не прикрыты — у fish свои ошибки, и какие, слышно только ухом.
Вот весь список на прослушивание, 29 мест на двенадцать слов: `ему` (8),
`далеко` (7), `метка` (3), `свои` (3), `шикнул`, `сопел`, `третьем`, `дубу`,
`сложены`, `правилу` — плюс `на лугу` (2) и `в Краю` (2) из следующего
абзаца.
Что fish прочла неверно — переписывается в сценарии и переозвучивается:
правилом это больше не чинится. Команда та же —
`node tools/check-stress-risk.mjs`.

**Два места оставлены двусмысленными нарочно.** «На лугу» — потому что
читается верно (это проверено, правило было нужно только дательному
«нашему лугу»), а луг — то самое место, с которого начинается сериал
и которым он кончается. «В Краю» — имя мира; переписать его значит
переименовать Край.

**Уходя от одной опасной формы, легко внести другую.** На этой правке
так вышло пять раз: «у края леса» → «у леса» (а это `л+еса` или `лес+а`),
«вдоль берега» → «вдоль воды», «с травы» → «с земли». Поймала проверка,
а не слух, — поэтому гонять её надо **после** правки, а не только до.

`audit-accents.py` — сплошной проход по словарю. Список подозрительных слов
руками всегда неполон: из тридцати шести моих догадок подтвердились шесть,
зато проход нашёл и то, о чём я не думал. Слова он проверяет поодиночке,
это быстрее; контекстные омографы («в горе» — гора или горе) ловятся
только на целых репликах, то есть `check-accents.py`.

Модель `tools/tts/models/v3_1_ru.pt` качается с
`models.silero.ai/models/tts/ru/v3_1_ru.pt`. Берётся **v3, а не v4**: v4
требует более свежий torch, чем стоит в окружении Easy Diffusion (1.13,
Python 3.8.5). Грузится из файла через `PackageImporter`, а не через
`torch.hub`.

Сжатие в MP3 делает браузер на сборке (lamejs): запись через `MediaRecorder`
шла бы в реальном времени — двенадцать минут на семьсот секунд речи.
WAV занимает 34 МБ, MP3 при 40 кбит/с — 4 МБ.

## Прослушивание ответа

Настройки вверху `js/app.js`: окно 30 секунд, четыре попытки, мягкая
подсказка после второй. Так сделано по жалобе из эксплуатации: посторонний
шум принимался за попытку ответить, и прослушивание обрывалось почти сразу.

* распознавание работает **непрерывно** и само перезапускается, пока окно не
  истекло. Движок на Android обрывается после паузы, и ребёнок, задумавшийся
  на три секунды, обнаруживал, что его уже не слушают;
* обрывки без настоящего слова (кашель, шуршание) не считаются попыткой;
* промах не обрывает прослушивание — считается и идёт дальше;
* **задумчивые звуки не считаются ответом** (`HESITATION` в `js/voice.js`).
  Ребёнок тянет «э-э-э», распознаватель присылает это готовой фразой,
  и раньше она шла за попытку: засчитывался промах, звучала подсказка,
  а настоящий ответ следом слушать было уже некому;
* подсказка ждёт тишины: если ребёнок говорил меньше двух секунд назад,
  мы молчим и не перебиваем;
* подсказка произносится с выключенным микрофоном, иначе рассказчика слышит
  он сам: звук идёт на телевизор и возвращается в телефон.

### Перезапуск распознавания

Жалоба из эксплуатации: «прослушивание заедает — само включается и тут же
выключается много раз подряд, ребёнок отвечает, а ответа нет». Причин было
четыре, все в цикле перезапуска, и первая достаточна сама по себе.

**Погашенный слушатель оживал.** Неудачный `rec.start()` внутри `onend`
уходил в `setTimeout(launch, 300)`, таймер нигде не хранился, `stop()` его
не гасил, а `launch()` на флаг остановки не смотрел. Значит после
`stopListening()` — во время подсказки, похвалы и даже на следующей сцене —
поднималось второе распознавание и дралось за микрофон с законным: каждый
`start()` обрывал чужой сеанс (`aborted`), тот немедленно стартовал снова.
Измерено на заглушке: после `stop()` старый код создавал ещё один экземпляр
и запускал его, новый не создаёт ни одного.

Остальные три усиливали: осиротевшие экземпляры не отцеплялись (`onend`
старого звал `start()` у нового), перезапуск шёл без паузы, а `onerror`
молчал обо всём, кроме запрета доступа.

Теперь так:

* у каждого сеанса своё **поколение**; обработчик чужого поколения молчит;
* **единственная точка перезапуска** с хранимым таймером, и она же первой
  строкой смотрит, не погашен ли слушатель;
* **отступ** у немых сеансов: 250 → 500 → 1000 → 2000 мс. Немой — это сеанс,
  **не вернувший ни одного результата**. Настоящий результат сбрасывает
  отступ: ребёнок, который просто помолчал, под лечение не попадает, потому
  что сеанс с его ответом считается удачным;
* **потолок трепыхания** — восемь немых сеансов подряд, и мы перестаём
  драться за микрофон (`onEnd('flapping')` → мягкое «нажми ответ внизу»).
  Немым окном это не считается и голос на историю не выключает: молчания
  не было, был отказ;
* `audio-capture` лечить перезапуском бессмысленно — выключаем голос, как
  при запрете доступа;
* **пока звучит рассказчик, микрофон не поднимается вовсе** (`isSpeaking()`
  поверх `isPlaying()` из `js/audio.js` и `speechSynthesis.speaking`).
  Измерено: за 2,5 секунды звучащей записи перезапусков ноль, после
  тишины — сразу же.

### Почему признак здоровья — результат, а не звук

Сначала немым считался сеанс «короче 400 мс и без единого звука», и это
не срабатывало **никогда**. Причину нашли по журналу от 22.10.2026 и
подсказал её заказчик: распознаватель на Android **подаёт системный сигнал**
в начале и в конце прослушивания, микрофон слышит собственный писк,
`onspeechstart` отмечается всегда. Значит «сеанс без звука» недостижим по
существу, отступ не рос ни разу, потолок не копился, а разбор журнала честно
писал «затыков 0» там, где ребёнок видел ровно затык.

Доказательство — в задержке до «речи», отсчитанной **от старта каждого
сеанса**: 971, 1012, 1044, 1046 мс у первых сеансов окна и 601, 635, 637,
683 у вторых. Два машинных кластера, слишком ровных для человека; у сеансов
с настоящим ответом задержка никогда не была меньше 1594 мс. Отсчёт именно
от старта сеанса закрыл и конкурирующую догадку про эхо с телевизора:
второй сеанс начинается через 2–4 секунды после реплики, хвост к этому
времени отзвучал, а кластер на месте. Прежний порог в 400 мс был вторым
запором на той же двери: короче 1225 мс сеансов на Android не бывает вовсе.

**Выключить писк из страницы нельзя.** В Web Speech API нет ничего, кроме
`continuous`, `interimResults`, `lang`, `maxAlternatives`, `grammars`,
`phrases`, `processLocally`, `quality` и `unspokenPunctuation` — проверено
перебором на Chrome 155. Сигналы играет системная служба распознавания,
до неё страница не дотягивается.

Поэтому лечится не причина, а её действие: признаком стал **результат**.
Проверяется это на заглушке — `node tests-listen.mjs` воспроизводит немой
сеанс по шагам (писк через секунду, `speechend`, конец, ноль результатов)
и требует, чтобы двадцать таких подряд были признаны затыком.

**Запасного выхода нет: проверено.** `processLocally: true` перевёл бы
распознавание на устройство мимо облачной службы Google — а сигналы играет
именно её обёртка, и вместе с писком ушла бы зависимость от сети, которой
у офлайнового приложения быть не должно. Ответ устройства пишется в журнал
при старте (`mic.probe` в `js/voice.js`) и виден в разборе строкой
«распознавание: на устройстве …, облачное …». На нашем телефоне там стоит
**`на устройстве unavailable, облачное available`** (журнал от 23.10.2026),
то есть распознавание только облачное и писк никуда не денется. Догадку
можно закрывать; лечится по-прежнему действие, а не причина.

### Одна фраза — одна попытка

Жалоба была не прямая, нашлось по журналу от 23.10.2026: все шесть переходов
на кнопки в тот вечер случились по поводу `misses`, и ни одного по молчанию.
Причина не в сопоставлении: распознаватель Android отдаёт долгую фразу
**нарастающими кусками**, и каждый кусок приходит отдельным готовым
результатом. Постороннее предложение из комнаты выглядело в журнале так:

```
услышано «Мам»          ПРОМАХ
услышано «Мам я»        ПРОМАХ
услышано «Мам я уже»    ПРОМАХ
услышано «Мам я уже»    ПРОМАХ   → ушло на кнопки: misses
```

То есть `MAX_MISSES = 4` выжигался **одним** чужим предложением, которое
ребёнок даже не произносил, а заложенные «четыре попытки, ответ с третьего
раза нормален» не давались вовсе. Так же прошли «какие мальчики» ×3,
«спортзал на балке знаешь» ×4, «сейчас пока в зале» ×4, «кашу» ×4.

Поэтому промахом считается только **первый** кусок фразы: продолжение той же
фразы попыткой не считается (`isSameUtterance` в `js/match.js`). Продолжение
считается **словами, а не буквами** — «тридцать» после «три» это новая
попытка, а не то же слово. Сами результаты при этом не выбрасываются: кусок
подлиннее может как раз попасть в ключ, и тогда ответ принимается.

Решение принимается в `onResult` и уходит в журнал полем `repeat` у
`mic.match`, а разбор печатает такой кусок как «то же, не в счёт». Иначе
разбор показывал четыре попытки там, где прозвучало одно предложение, —
а вся его польза в том, чтобы считать разы, а не записи.

## Журнал событий

`js/log.js`. Телефон — движок истории, консоли у него нет, а смотрит ребёнок
на телевизор: дефект вроде описанного выше ловится только записью. Процедура
взята целиком у соседнего проекта `run-game` (`js/log.js` там же) и не
изобреталась заново.

* **IndexedDB, а не `localStorage`**: тот синхронный и подвешивает кадр.
* Очередь со сбросом **раз в две секунды** и на уходе со страницы: самые
  ценные записи — те, после которых приложение умерло.
* **Повторы подряд склеиваются** в одну запись со счётчиком `_n`. Это не
  украшение: затык прослушивания — это и есть поток одинаковых событий,
  и без склейки он вытеснил бы из журнала все прошлые сессии.
* Потолки 5 МБ и 20 сессий, чистятся самые старые; текущая не удаляется
  никогда, иначе журнал съест сам себя.
* Любая ошибка базы **молча выключает журнал** — история важнее.
* Сессия — один запуск приложения, а не одна история: интересны как раз
  случаи, когда история не доиграна.

**Передача.** Кнопка «Выгрузить журнал» внизу главного экрана, рядом
с «Обновить приложение», такая же мелкая и серая: она для взрослого. Одним
нажатием журнал кладётся файлом в «Загрузки» **и** открывается «Поделиться».
Именно в таком порядке и обязательно оба: шторку можно закрыть случайно,
и файл при этом пропасть не должен.

**Выгруженное убирается в два приёма.** В этот раз сессия помечается,
а удаляется та, что была помечена в прошлый. Удалять сразу нельзя: признак
удачной загрузки врёт — браузер отказывает **после** клика и молча
(кончилось место), и приложение написало бы «очищено», снеся единственные
записи. Поэтому первая выгрузка ничего не освобождает, и подпись об этом
говорит прямо.

**Пишутся не только события микрофона.** Одного здоровья прослушивания
оказалось мало: жалоба «верный ответ не приняли» по такому журналу не
проверяется вообще никак — не видно ни сцены, ни вопроса, ни услышанного.
Так и нашли подстроку в сопоставлении: диагноз пришлось строить на памяти
взрослого, а лог лишь подтвердил счёт промахов. Поэтому в журнал идут:

| Событие | Что в нём |
| ------- | --------- |
| `story.open` | какая история и с какой сцены |
| `scene.enter` | id сцены и направление ухода слоёв |
| `scene.missing` | `next` указал в несуществующую сцену — опечатка иначе невидима |
| `task.ask` | вид, предел, область, **вопрос целиком**, верный ответ и варианты |
| `mic.match` | услышанное, остальные догадки движка, к какому варианту уехало, с какой ошибкой, промах ли |
| `mic.giveup` | повод перехода на кнопки: `misses`, `window` или `flapping` |
| `answer.pick` | чем ответили и как — голосом или кнопкой |

Задание создаётся заново на каждом заходе, поэтому `task.ask` — единственный
способ узнать потом, на какой вопрос ребёнок отвечал.

Повод в `mic.giveup` различает две совершенно разные беды: `misses` значит
«ребёнок отвечал, а его не понимали» (дефект сопоставления), `window` —
«молчал» (дефект микрофона или ребёнок отвлёкся). До этого оба случая
выглядели в журнале одинаково — `mic.window.end` с поводом `stop`.

**Разбор** — `tools/log-report.mjs`, принимает выгруженный файл и печатает
окна прослушивания: сколько было сеансов, перезапусков и с какими паузами,
какие отказы, дошло ли до ответа, а также вопрос сцены и построчно —
услышанное с вердиктом. Считалка (`report()`) отделена от печати
и проверяется из node на синтетических сессиях — `tests-log.mjs`, без
телефона и без настоящего журнала.

**Сцена и задание приходят до окна, а нажатие кнопки — после.** Вопрос
сначала создаётся и читается вслух, микрофон поднимается потом; а кнопку
ребёнок жмёт, когда голос уже сдался и окно закрыто. Поэтому `windows()`
держит сцену с заданием вне окна и отдаёт каждому следующему, а позднее
нажатие приписывает последнему закрытому окну той же сцены. Без этого окно
не связать ни с вопросом, ни с ответом.

**Считать надо разы, а не записи.** Повторы склеены, и `_n` у одной строки
бывает сотней. Это главная ловушка разбора: разница между «оборвалось один
раз» и «оборвалось сто раз» и есть весь его смысл.

## Темп сцены и блокировка кнопок

Голос раньше ждал, пока доедут все слои и персонажи, — почти секунда тишины
на каждой сцене. Теперь рассказ начинается через `SCENE_LEAD_MS` (420 мс),
не дожидаясь конца анимации: она доигрывает уже под голос.

Пока говорит рассказчик, кнопки **заблокированы** и приглушены. Раньше они
были активны всегда, и при быстрых нажатиях сцены сменялись быстрее, чем
смолкал звук, — реплики соседних сцен накладывались. Блокировка снимается
ровно тогда, когда вопрос дочитан.

Остановка звука глушит **все** запущенные записи, а не только последнюю
(`playing` — Map в `js/audio.js`). Ожидание завершается явно вызовом
`finish(false)`, а не по событию ошибки от браузера: это событие приходит
не везде, и повествование зависало, не дождавшись конца реплики.

**Длительность записи бывает неизвестна.** MP3 от lamejs идут без заголовка
с продолжительностью, и браузер до конца загрузки отдаёт `duration = Infinity`.
Отсюда два правила в `js/audio.js`:

* страховочный таймер считается только по конечной длительности. Прежний
  расчёт `(duration || 10) * 1000 + 1500` при Infinity давал Infinity,
  а `setTimeout` с таким значением срабатывает **немедленно** — ожидание
  закрывалось мгновенно, рассказ уходил к следующей реплике, и две фразы
  звучали разом. Измерено: накладки на каждой сцене, по 0,3 секунды
  после начала первой реплики;
* «прозвучало ли» (`enough`) при неизвестной длительности определяется
  по позиции, а не по доле от неё: `currentTime >= Infinity * 0.5` всегда
  ложь, и движок звал бы ещё и браузерный синтез поверх записи.

**Закрыть ожидание и забыть запись — разные вещи.** Элемент покидает
`playing`, только когда действительно смолк. Если ожидание закрылось раньше
(сработала страховка), запись обязана остаться под присмотром: иначе
остановить её при смене сцены уже нечем.

Кнопка «»» левее бургера обрывает озвучку и открывает ответ досрочно. Она
трогает только речь (`skipToken`), не ход сцены (`token`): иначе нажатие
во время похвалы оставило бы ребёнка на той же сцене.

## Прогресс

Телевизор умеет увести со страницы помимо нашей воли: кнопка микрофона на
пульте открывает системный голосовой поиск. Перехватить её страница не может
— её обрабатывает прошивка раньше, чем событие дойдёт до страницы.

Поэтому место сохраняется в `localStorage` при каждой смене сцены, и на
главном экране появляется «Продолжить». На финале запись стирается.
`renderResume()` вызывается не только при загрузке, но и в `backToHub()` —
иначе остаётся кнопка на уже пройденную историю.

## Кнопка «Обновить приложение»

Внизу главного экрана. Нужна потому, что установленное приложение берёт всё
из кэша, а новую `sw.js` браузер перечитывает когда сочтёт нужным — на
телевизоре новая версия могла ждать сутки.

Кнопка зовёт `registration.update()` и перезагружает страницу по
`controllerchange`. Кэш руками **не стирается**: без сети стёртый кэш оставил
бы ребёнка вообще без приложения, а воркер сначала скачивает всё в новый кэш
и только потом удаляет старый — не вышло, значит осталось как было. При
`navigator.onLine === false` кнопка даже не пробует.

Нажатий нужно два (второе — в течение шести секунд): кнопка стоит на одном
экране с обложками, и случайное нажатие ребёнком не должно уводить
в перезагрузку. По той же причине она мелкая и серая, а не «плакатная».

## Что ещё заложено в движке

* Микрофон включается **только после** того, как рассказчик замолчал — иначе
  звук с телевизора возвращается в микрофон и распознаётся как ответ.
* Два промаха подряд → мягкая подсказка (`NUDGE_AFTER`), четыре → переход
  на кнопки (`MAX_MISSES`). Ребёнок не застревает, но и не теряет попытку:
  ответ с третьего раза для семилетнего совершенно нормален.
* Числа сопоставляются и словом, и цифрой; опечатки распознавания прощаются
  по расстоянию Левенштейна: до 2 символов в длинных словах, 0 в коротких.
  Список числительных в `js/match.js` доходит **до двадцати** — ровно до
  предела счёта в заданиях, иначе цифра второго десятка не узнаёт слово.
* **Ключ ищется словами, а не подстрокой.** Движок Android отдаёт
  числительное цифрами, и `phrase.includes(key)` находил ключ «2» внутри
  услышанного «12»: верные «двенадцать», «двадцать», «одиннадцать» уходили
  в «два», «два», «один» — то есть верный ответ засчитывался промахом, а
  после четырёх таких промахов сцена переходила на кнопки. Проверка идёт
  по последовательности слов (`hasWords`), все пары второго десятка
  закрыты в `tests-match.mjs`.
* **Служебное слово ответом не бывает** (`STOPWORDS` в `js/match.js`).
  Союз «и» лежит внутри ключей «шерсть и вода», «палки и уголёк», и сравнение
  по словам давало ему точное совпадение: услышанное «железо и» уезжало
  в «Шерсть и вода», то есть в заведомо неверный вариант — а верный ответ
  («железо» против «железные») не ловился вовсе. Тем же путём одинокое «по»
  выбирало между «По мосту над лавой» и «По песку» **порядком перебора**,
  а не смыслом: ребёнок мог сказать «по песку» и уехать на мост. Внутри
  целой фразы такие слова по-прежнему считаются — запрет только на одиночное.
  Найдено по журналу от 23.10.2026.
* **Целая фраза сильнее одного слова** (`PART_PENALTY`). Попадание одним
  словом ключа получает надбавку 0.5, поэтому «по песку» уезжает в «По песку»,
  а не в тот вариант, что стоял в списке раньше. Надбавка дробная нарочно:
  точное слово (0.5) обязано идти впереди фразы, расслышанной с ошибкой (1).
* Из шести догадок распознавателя берётся **самая точная**, а не первая
  подошедшая: приблизительное совпадение не должно обгонять точное.
* Стрелки / Enter / цифры 1–9 — управление пультом телевизора.
* Wake Lock держит экран включённым, Service Worker кэширует всё офлайн.
* Озвучка не может уронить повествование: ни отсутствие голоса, ни отказ
  движка, ни потерянное событие `onend` не оставят историю висеть — окончание
  реплики определяется опросом синтезатора, а не только событием.
* Доступ к микрофону, полный экран и блокировка ориентации обёрнуты в
  `withTimeout`: эти обещания умеют не завершаться никогда, и приложение
  зависало на «Готовим…».
* При смене истории `el.choices` и `el.text` очищаются — иначе кнопки
  прошлой сцены остаются в DOM и стрелки пульта действуют на них.

## Размеры шрифтов

Сокращённую запись `font: 700 4.6vmin/1.15 inherit` использовать **нельзя**:
`inherit` в ней недопустим, браузер отбрасывает правило целиком, и кнопка
остаётся с размером по умолчанию — тринадцать пикселей. Выглядит это как
«правка не применяется». Свойства шрифта задаются по отдельности.

Там же: `[hidden]{display:none!important}` обязателен, потому что
`.gate{display:flex}` и `.stage{display:grid}` перебивают браузерное
`[hidden]`.

## Графика

Сцена собрана из четырёх слоёв плюс персонажи — они двигаются с разной
скоростью, и получается глубина вместо плоской подмены кадра.

| Слой     | Размер     | Что на нём                         |
| -------- | ---------- | ---------------------------------- |
| `sky`    | 1920×1080  | градиент неба                      |
| `stars`  | 1920×1080  | звёзды или светило, прозрачный     |
| `far`    | 1920×1080  | холмы, дальний лес, дымка          |
| `near`   | 1920×1080  | земля, вода, кулисы по краям       |
| персонаж | по силуэту | прозрачный фон, обрезан по контуру |

### Контракт на картинки

Две мерки, на которых всё держится:

- **Линия земли — 70% высоты кадра.** Если ставить землю по нижнему краю,
  персонажи уйдут за панель с текстом.
- **У файла персонажа `width`/`height` обязаны совпадать с `viewBox`.**
  Иначе браузер берёт пропорции из атрибутов, рисунок летербоксится внутри
  квадрата, и герой висит в воздухе на высоту пустого поля.

**Чистая зона кадра — замер, а не прикидка.** Текст занимает **3…65%
ширины и всё, что ниже 56% высоты**: панели с фоном нет, строки лежат прямо
на картинке и растут вверх по мере длины. Свободны, значит, две полосы —
**выше 56% по всей ширине** и **правее 65% до самого низа**.

Прежняя запись «ниже 74%» неверна и стоила трёх одинаковых промахов подряд:
на девятом дне горку железа закрыла собой Алекс, на десятом щиты легли под
панель, на одиннадцатом туда же ушли ловушки — и каждый раз пряталось ровно
то, что ребёнок должен сосчитать или разглядеть. **Предмет задания ставится
в чистую полосу**, а не «на землю рядом с героем». Мерить так:

```js
const f = document.querySelector('.frame').getBoundingClientRect();
const t = document.querySelector('#text').getBoundingClientRect();
// t.top / f.height — где начинается текст; t.right / f.width — где он кончается
```

Случайность в генераторах детерминированная: один и тот же запуск даёт те же
файлы, иначе в истории правок не видно, что реально изменилось.

WebP вместо PNG обязателен: тот же комплект в PNG весит 8.7 МБ против 170 КБ,
а он целиком уходит в офлайн-кэш.

### Что чем рисуется

| Слой | Чем | Почему |
| ---- | --- | ------ |
| `sky` | нейросеть | мягкие градиенты и свечение — вектору недоступны |
| `stars` | вектор | через img2img звёзды либо раздуваются во второе светило, либо вымываются; вектор ещё и мерцает |
| `far-*` | нейросеть | атмосферная дымка и глубина |
| `near-*` | вектор | нужен чёткий силуэт; в Minecraft чёткость кубов — главное в стиле |
| персонажи | вектор | Stable Diffusion не умеет прозрачный фон и не держит одного героя между кадрами |

У каждого зверя своя палитра — она задаётся прямо в его функции
в `tools/make-art-mc.mjs` (`cow()`, `sheep()`, `wolf()`), и общей
константы на всех нет нарочно: одна палитра давала фиолетовый зверинец.
Тона теплее и светлее фона — на синей ночи холодный персонаж сливается
с задником.

### Easy Diffusion

`D:\EasyDiffusion`, модель `deliberate_v2`, RTX 3060. Работаем **через
HTTP-API на порту 9000**, не через браузер: картинки нужны пачками
с одинаковыми настройками.

```
node tools/ed-generate.mjs --prompt "..." --out tools/out/x.png
node tools/paint-layers.mjs           # все слои разом
node tools/paint-layers.mjs sky       # только один
```

Запуск сервера (первый старт ~3 минуты — модель грузится в видеопамять,
дальше ~8 секунд на картинку):

```powershell
Start-Process cmd.exe -ArgumentList '/c','"D:\EasyDiffusion\Start Stable Diffusion UI.cmd"'
```

Из Git Bash через `cmd //c` **не запускается**: `cmd` читает первое слово
имени файла «Start» как свою встроенную команду и ищет файл «Stable».

**img2img, а не генерация с нуля.** Композиция берётся с наших векторных
слоёв: линия земли на 70%, свободный центр под персонажей, кулисы по краям.
Генерация «с нуля» вернёт красивую картинку с землёй где попало, и персонажи
повиснут в воздухе. `prompt_strength`: небо 0.5, дальний план 0.45.

Конвейер:

1. `tools/raster.html` + `window.rasterInit` — SVG в растр 768×432. Браузер
   здесь единственный доступный растеризатор: ни ImageMagick, ни Inkscape,
   ни cairosvg на машине нет. Записывать файлы ему помогает `POST /save`
   в `serve.js` (только для локальной разработки).

   Страница открывается браузером Playwright MCP на
   `http://localhost:8099/tools/raster.html`, а функции зовутся через
   `browser_evaluate`. Руками кликать нечего — у всех четырёх окон
   (`rasterInit`, `composeLayer`, `composeCover`, `transcodeAudio`)
   интерфейс только программный.
2. `tools/paint-layers.mjs` — img2img + апскейл RealESRGAN ×4 до 3072×1728.
3. `window.composeLayer` — возврат прозрачности и сжатие до 1920×1080 в WebP.

Маска при сборке бывает двух видов: **силуэт из того же SVG** — для слоёв,
сквозь которые должно быть видно небо; **мягкий вертикальный градиент** —
для дальнего плана (жёсткий силуэт срезает написанную дымку над лесом,
и слой становится плоским набором тонких фигур).

Промежуточные файлы (`tools/init/`, `tools/painted/`) в приложение не
попадают, но их стоит держать: пересобрать слой из них — секунда,
сгенерировать заново — отдельный прогон.

## Анимации

`js/stage.js`, вызывается из `app.js`.

| Событие | Что происходит |
| ------- | -------------- |
| вход в локацию | слои выезжают с разной скоростью, персонажи появляются с подскоком |
| выход | слои уходят в сторону выбранного пути |
| выбор пути | `"dir"` у варианта задаёт направление |
| верный ответ | герой подпрыгивает, разлетаются искры |
| верный ответ в сцене боя | кадр встряхивает, искры крупнее и теплее (`"fx": "impact"`) |
| неверный ответ | кнопка покачивается, герой удивлённо наклоняется |

Неверный ответ намеренно без красного и без резких движений: это не ошибка,
а приглашение попробовать ещё раз. При системной настройке «меньше движения»
анимации не отключаются, а сжимаются почти в ноль — код остаётся один,
а ребёнка с укачиванием не трясёт.

## Стенд прослушивания

`http://localhost:8099/tools/listen.html` (нужен `node serve.js`). Выбор
истории — и дальше вся она подряд: повествование, обе ветки развилки,
задания со **всеми** вариантами из пула, подсказки, похвалы и служебные
реплики. У каждой строки показан её **идентификатор** — то самое имя файла
в `assets/audio`; по щелчку он копируется, и реплику сразу видно чем
переозвучивать.

Кнопка ▶ у строки читает одну реплику, у сцены — сцену подряд, вверху —
всю историю. Задания в сквозном прослушивании берутся по **первому**
варианту: галочка «все варианты» включает остальные, но тогда это уже
не история, а проверка пула (у одного ключа их до десяти).

Неозвученная реплика горит красным — то же, что скажет `check-voices.mjs`,
только видно, где именно в сюжете дыра.

**Порядок реплик стенд не знает сам.** Он берёт его из
`tools/tts/utterances.mjs` — общего модуля, которым пользуется и сверка;
идентификатор из `js/audio.js`, ключ пула из `js/tasks.js`. Это сделано
нарочно: третья копия порядка однажды разойдётся с движком, и стенд станет
показывать не то, что слышит ребёнок. По той же причине в `serve.js`
добавлен тип для `.mjs` — браузер отказывается грузить модуль, отданный
как `application/octet-stream`.

## Что проверять

После каждой правки — пять файлов тестов и три машинные сверки, затем
прогон в браузере:

```
node tests-tasks.mjs && node tests-match.mjs && node tests-voice.mjs
node tests-log.mjs && node tests-listen.mjs && node tests-story.mjs
node tools/check-speech.mjs      # правила письма — ПАДАЕТ на нарушении
node tools/check-stress-risk.mjs # опасные формы — советует, код всегда 0
node tools/check-voices.mjs      # всё ли озвучено и сходятся ли роли
node tools/check-story.mjs       # устройство истории — ПАДАЕТ на дефекте
```

`check-story.mjs` — про саму историю, а не про её озвучку: граф сцен
(битый `next`, недостижимая сцена, есть ли финал, **есть ли из каждой сцены
дорога к финалу**), длина текста, задание без `types`/`topic`, тупиковый
выбор без реплики. Плюс советы, которых больше нигде нет:

* **`fact-not-on-all-paths`** — слово звучит как известное в сцене, до
  которой ведёт путь, нигде его не вводивший. Реплика варианта при этом
  считается принадлежащей **ветке**, а не сцене: сказанное в `say` одной
  кнопки известно только тому, кто её нажал. Это главная проверка файла
  и перенос жёсткого правила из `danjdewhurst/story-skills` — «проза
  перекрёстка не должна быть верна только на одном входящем пути».
  Ровно так терялся крючок тринадцатого дня;
* **`new-word`** — слово, которого не было нигде в сериале, перешло
  во вторую сцену: кандидат в «названо и не объяснено», так ловится «оберег»;
* **`rejoin`** — перечень сцен, куда сходятся ветки: там и прячется первое;
* **`hook-not-closed`** — крючок прошлой серии не закрыт (поля ниже);
* **`uneven-labels`** — подпись вдвое длиннее соседней читается ребёнком
  как правильный ответ;
* **`rare-cast`** — персонаж не выходил несколько историй подряд (мера
  редкости для пасхалки);
* **`speaker-voice`** (дефект) и **`speaker-named`** (совет) — реплику
  читает не тот голос. Дефект — когда реплика начинается со знака роли
  («Хм-хм» у жителя, «Хрю» у свинолюда), а голос другой. Совет — когда
  в последнем предложении перед кавычками назван другой персонаж с голосом.
  `check-voices` такого не видит: роль считается верно, неверен говорящий.

**Разобранную находку не глушат правкой текста** — её записывают
в `tools/story-exemptions.json` с причиной, и отчёт печатает, сколько
погашено. Приём перенесён оттуда же. Без него полный прогон был бы красным
всегда: у сериала 105 сцен долга по длине и шесть заданий без `topic`
в первом дне, а прогон, который красен всегда, читать перестают.

Считалка отделена от печати и проверяется `node tests-story.mjs`
на синтетических историях. Это не формальность: обход путей ломается молча,
и на настоящем четырнадцатом дне тест проходил бы и со сломанной считалкой —
тот случай уже починен.

У неё **два порога длины, и оба замерены по всему сериалу**: прогнаны все
140 сцен на кадре 1600×900, каждая своей прозой и худшим вопросом своего
ключа. Самая короткая сцена, у которой верх панели ушёл ниже контрактных
56%, — 185 знаков; самая длинная, у которой удержался, — 187. Обрыв, значит,
не точка, а полоса 185…187, и внутри неё решают сами слова: где встанут
переносы, столько и будет строк. Поэтому дефект объявляется выше **184** —
ниже самой короткой замеренной поломки, а 179…184 идёт советом «померяй
в прогоне».

**Считать надо то, что реально встанет в панель**, а это у двух видов сцен
разное: у задания `text + ' ' + вопрос` (так склеивает `js/app.js`), а у
развилки только `text` — поле `prompt` в панель не попадает вовсе, оно лишь
звучит. Первая версия сверки прибавляла `prompt` и забывала пробел, то есть
завышала длину у развилок и занижала у заданий.

Долг по длине **выплачен**: 99 сцен в двенадцати сериях переписаны короче,
и записи `too-long` убраны из исключений — иначе они прятали бы новые
поломки. Контрольный замер: из 140 сцен ниже контракта ноль, худшая 61.4%.

Сверка ударений стояла только в шаге 5 «Как добавить комикс», и этого
мало: прозу правят и вне добавления истории. Так в тринадцатом дне
ушло в озвучку «Туман разошёлся» с ударением на первый слог — текст
правили, а советчика не спросили.

`check-speech.mjs` — единственная из них, которая выходит с ненулевым кодом.
Так сделано нарочно: прозы про запретные слова оказалось мало. В граблях
стояло, что «кладка» заменена, — её всё равно написали восемь раз в
двенадцатом дне, а в десятом она и не исчезала. Текст в файле не
срабатывает в ту минуту, когда пишешь сценарий; проверка срабатывает.

Прогон истории целиком: обе развилки, все задания, неверный ответ
с подсказкой, финал, возврат к выбору истории. Смотреть при этом:

* вопрос каждой игры **про то, что на экране**;
* в каждой локации персонажи стоят на земле и не перекрыты панелью текста;
* кнопки заблокированы во время озвучки, кнопка пропуска работает;
* одновременно играет не больше одной записи. Проверять это надо замером
  позиций: завести список всех созданных `new Audio()` и каждые 200 мс
  смотреть, у скольких `currentTime` реально сдвинулся. Подсчёт по событиям
  врёт, а `document.querySelectorAll('audio')` не находит вообще ничего.

После `collect.mjs` сверять, что прежние идентификаторы не исчезли из
манифеста: иначе озвучка старых историй осыплется.

`node tools/check-voices.mjs` делает это машинно: проходит все истории
в том же порядке, что и движок, и говорит, у какой реплики нет записи.
Пустой ответ значит «всё озвучено, роли сходятся». Проверка берёт `clipId`
из `js/audio.js` — из той самой копии, которой приложение ищет файл,
а не из конвейера: разойдутся две копии — она это и покажет.

На боевом адресе: `sw.js` отдаёт новый номер кэша, `assets/audio/index.json`
вырос, новые реплики играют.

## Грабли

Это то, что уже стоило времени и из кода не видно.

| Симптом | Причина |
| ------- | ------- |
| «Правка CSS не применяется» | `inherit` в шорткоде `font` — правило отброшено целиком |
| «На localhost старый код» | Service Worker; он намеренно не регистрируется на localhost, старые кэши удаляются |
| «На телевизоре старая версия» | не сменён `CACHE` в `sw.js` |
| `ReferenceError` на `sleep` | `sleep` и `withTimeout` должны быть **объявлениями функций**, их зовут выше по файлу |
| `torch.hub` падает при загрузке модели | в пути профиля кириллица («Администратор»); грузить из файла через `PackageImporter` |
| Easy Diffusion не стартует из Git Bash | `cmd //c` ломается на имени «Start Stable Diffusion UI.cmd»; только `Start-Process` |
| Персонаж висит в воздухе | `width`/`height` в SVG не совпадают с `viewBox` |
| `collect.mjs` падает на разборе истории | читает собственный `stories/tasks-pool.json`; он исключается по имени |
| Приложение замерло на «Готовим…» | обещание микрофона или полного экрана не завершилось; нужен `withTimeout` |
| `grep` по кириллице в конвейере врёт про провал | проверять результат подсчётом файлов, а не кодом возврата |
| Две реплики звучат разом | `duration` у MP3 бывает `Infinity`, и `setTimeout(Infinity)` срабатывает сразу — см. «Темп сцены» |
| Замена взрослого слова не помогла | синоним такой же отвлечённый: «оберег» → «знак» → снова «о чём речь?». Заменять надо НЕ синонимом, а тем, что видно в кадре: тыква, железо, ворота |
| Ребёнок не понял слово из реплики | взрослый лексикон. Слушать историю надо не только на ударения — см. «Слова, которых ребёнок не знает» |
| Слово звучит скомканно, хотя ударение верное | fish комкает некоторые слова целиком («колокол», «голем»). Правилом не чинится: фраза обходится стороной («над крышами пошёл звон») или слово заменяется прозвищем («Железный») |
| «все» прочитано как «всё» | для fish это одно слово, и выбирает она сама; метки ударения нет. Обходится другим подлежащим: «и Стив заулыбался» |
| Крючок прошлой серии теряется | он упомянут только на необязательной ветке. Обходить надо ВСЕ пути и проверять не только то, что объяснено, но и то, что закрыто — см. `STORYLINE.md`, день 14 |
| Новый предмет повторяет чужой рецепт | «тыква с железом» — это голем девятого дня, а не оберег. Перед тем как вводить предмет, искать его составные части по прежним историям |
| Предмет назван в нескольких сценах, а что это — не сказано | каждая сцена по отдельности осмысленна, и дыру видно только на слух целиком. Называть своими словами в ПЕРВОЙ сцене, где предмет появляется, и устами героя — см. `STORYLINE.md`, день 14 |
| История звучит пересказом, героев не слышно | девять десятых реплик у рассказчика. Правило и замер — в `STORYLINE.md`, «Герои и тон»: то, что герой мог сказать сам, отдаётся ему, а раскладка по ролям видна до синтеза в `fish.mjs --dry` |
| Слово звучит не с тем ударением | омограф; правило в `tools/tts/accents.json`, затем `render.py --restress` |
| Ремарку «— сказал он —» произносит голос персонажа | она стоит внутри «ёлочек»; вынести перед кавычками |
| Реплику варианта читает не тот голос | `collect.mjs` и `app.js` по-разному считали роль; порядок — вариант, сцена, история |
| Житель говорит голосом Стива | у сцены нет своего `voice`, и сработал голос истории. Так было пять раз за сериал (дни 6, 10, 12, дважды 14). Ловит `check-story`, код `speaker-voice` |
| Правило ударения сделало хуже | модель ставила верно; сверять со словарём, а не с ощущением |
| Проверка «играет ли звук» ничего не находит | записи создаются как `new Audio()` и в DOM не попадают; `document.querySelectorAll('audio')` пуст — мерить надо по `currentTime` |
| Микрофон мигает, ответ не слышен | погашенный слушатель оживал отложенным запуском — см. «Перезапуск распознавания» |
| Защита от зацикливания «никогда не срабатывает» | признаком считался звук, а распознаватель пищит сам и слышит себя; признак — результат, см. «Почему признак здоровья — результат» |
| Рассказчик меняет голос посреди истории | часть корпуса озвучена другим движком; имя файла про движок не знает — переозвучивать надо целиком |
| Реплика звучит оборванной, будто будет продолжение | точка стоит снаружи «ёлочек» и в запись не попадает; дописывается при синтезе — см. «Точка в конце реплики» |
| Правило из `accents.json` не действует | корпус озвучен fish, а правила читает только `render.py` |
| Вся история звучит чужим голосом | `loadIndex()` запомнил **пустой** индекс после одного сбоя сети; `if (index)` считает пустое множество ответом |
| Предмет задания не виден в кадре | он ниже 56% высоты и левее 65% ширины — там текст; см. «Контракт на картинки» |
| Верное число засчитано неверным | ключ-цифра был подстрокой услышанного: «12» попадало в «два». Сопоставление идёт словами |
| Старый журнал молчит про сцены и ответы | выгрузки до `scene.enter`/`task.ask`/`mic.match` разбираются по-прежнему, но новые числа у них нулевые — там этих событий нет |
| Правка ударения внесла новое ударение | «у края леса» → «у леса»: `л+еса` или `лес+а`. Проверку гонять после правки |
| Новый файл в `js/` ломает офлайн | список корневых файлов в `tools/make-sw.mjs` задан **руками**; каталоги собираются с диска, а `js/` нет |
| Текст залез на персонажей | сцена длиннее четырёх строк (~170 знаков): верх панели уезжает с 56% до 47%. Мерить `#text` в прогоне, а не считать на глаз |
| Хромакей стёр слой начисто | рисунок темнее допуска от init-подложки `[10, 20, 48]`. Силуэту собирать маску из того же SVG (`keepAlpha`), хромакей — только заметно светлее подложки |

| Слой нарисован, а в кадре его нет | его забыли вписать в `bg` сцены: генератор отдал файл, сценарий про него не знает |
| Герой говорит ровным голосом там, где важное | теги эмоций у fish не работают ни в каком виде, проверено; лечится восклицательным знаком и ремаркой рассказчика — см. «Эмоции» |
| У нового персонажа голос прежнего героя | освободившаяся роль отдана новому: у fish голос узнаётся, шесть дней разницы ребёнка не обманут. Заводить свою роль; видно до синтеза раскладкой `fish.mjs --dry` |
| Ребёнок ответил верно, а уехало в другой вариант | союз «и» или предлог из многословного ключа дал точное совпадение сам по себе; служебные слова одиночкой не матчатся — см. «Что ещё заложено в движке» |
| Четыре промаха за одну чужую фразу | распознаватель отдаёт фразу нарастающими кусками, каждый приходил отдельной попыткой — см. «Одна фраза — одна попытка» |
| Подсказка загадки звучит обрубком | `why` подставляется внутрь «Подумай: два из них — это ___. А третий?» и должен быть именной группой. Ловилось дважды, оба раза выводом `check-voices.mjs`, а не глазами по коду |

## Чего не делать

* **Не пытаться оживить голосовой ответ в браузере телевизора.** Проверено
  на месте: микрофон отдаётся браузеру только при удержании кнопки пульта,
  а удержание уводит на системный поиск. Условия несовместимы, со стороны
  страницы не обходятся. Приложение само замечает глухой микрофон и
  отключает голос до конца сеанса; настройка запоминается. На телевизоре
  история полностью проходится пультом.
* **Не добавлять в `countable` слова женского рода** — см. «Задания».
* **Не отдавать освободившуюся роль новому персонажу** — у fish потолка
  в пять дикторов нет, экономить роли незачем. См. «Голоса и роли».
* **Не озвучивать варианты ответа наполовину** — см. «всё или ничего».
* **Не публиковать `tv.jpg`** — на снимке серийный номер телевизора, файл
  в `.gitignore` и должен там остаться.
* **Не дублировать это в README.** README — про проект для человека.

## Как писать код (из andrej-karpathy-skills)

Источник: https://github.com/multica-ai/andrej-karpathy-skills/blob/main/CLAUDE.md

Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

### 1. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

### 2. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

### 3. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it - don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: Every changed line should trace directly to the user's request.

### 4. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" → "Write tests for invalid inputs, then make them pass"
- "Fix the bug" → "Write a test that reproduces it, then make it pass"
- "Refactor X" → "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:
```
1. [Step] → verify: [check]
2. [Step] → verify: [check]
3. [Step] → verify: [check]
```

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

**These guidelines are working if:** fewer unnecessary changes in diffs, fewer rewrites due to overcomplication, and clarifying questions come before implementation rather than after mistakes.
